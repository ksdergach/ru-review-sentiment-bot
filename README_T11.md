# T11 — финальный голосовой тест: состав и фиксация

Задача: [#13](https://github.com/ksdergach/ru-review-sentiment-bot/issues/13).
36 голосовых отзывов о фильмах для финальной оценки влияния Whisper в T14
([#17](https://github.com/ksdergach/ru-review-sentiment-bot/issues/17)). Модели
и протокол оценки до этого фиксируются в T12
([#15](https://github.com/ksdergach/ru-review-sentiment-bot/issues/15)).
Набор не используется для обучения, выбора Whisper, классификатора или настроек.
Whisper и классификатор на этих записях не запускались.

## Как собран набор

Ниже описана фактически выполненная процедура; этот текст оформлен после сбора.

1. Подготовлены 36 новых сценариев коротких киноотзывов (19–25 слов), по 9 на диктора.
   Пересечений с train/validation/test и отладочными материалами T08 проверка
   ниже не нашла.
2. Четыре реальных диктора прочитали сценарии своим голосом; синтез речи не применялся.
   Пять записей сделаны с умеренным бытовым шумом.
3. Записи одного диктора сконвертированы в OGG/Opus; все 36 окончательных файлов — OGG/Opus.
4. Пользователь (координатор набора) прослушал все 36 записей и сверил каждую транскрипцию с произнесённым.
   Все эталоны совпали со сценариями.
5. Два разметчика, не являющиеся дикторами, независимо оценили текст каждого эталона
   по правилам [docs/team_plan.md](docs/team_plan.md), разделы 3 и 8
   (`negative=0`, `neutral=1`, `positive=2`). Обезличенные ID: `R01` — столбец
   «Метка А», `R02` — «Метка Б»; состав разметчиков не менялся.
6. Метки согласованы без ответов моделей. Разногласий не было ни по одной из 36 записей,
   неоднозначных случаев не отмечено. Итог: 12 negative, 12 neutral, 12 positive.
7. Состав зафиксирован до финальной оценки; записи не исключаются по результатам моделей.

Пункты 2, 4–6 в части слушания, независимости и личностей — подтверждения людей,
записанные в [reports/voice_test/human_confirmation.json](reports/voice_test/human_confirmation.json).

## Где лежат данные

Аудио, таблица и приватный манифест хранятся вне Git, в игнорируемой `artifacts/t11/`:

```
artifacts/t11/T11_dataset.xlsx           таблица координатора (2 листа)
artifacts/t11/raw_audio/voice_NNN.ogg    36 записей OGG/Opus
artifacts/t11/manifest.json              приватный манифест (создаёт валидатор)
```

Оригинал находится в закрытой общей папке команды. Перед проверкой положите
окончательные файлы по этим путям.

Структура таблицы:

- лист `02_Записи`: ID, участник, сценарий, имя файла, число слов сценария, шум,
  дословная транскрипция и отметка о сверке человеком;
- лист `03_Сведение_меток`: ID, участник, метки А и Б, согласованная метка,
  спор, причина неоднозначности и отметка о подтверждении человеком.

Валидатор ищет строку заголовков по названиям столбцов.

Приватный манифест содержит по каждой записи:

- `record_id` и обезличенный `speaker_id` (S01–S04 по порядку первого появления в таблице);
- путь, SHA-256, размер и длительность аудио;
- эталонную транскрипцию и её SHA-256;
- метки `R01` и `R02` с ID разметчиков и согласованную метку;
- признаки спора, неоднозначности и шума.

Имён участников в манифесте нет.

В Git хранятся только этот файл и файлы в `reports/voice_test/`:

- [composition.json](reports/voice_test/composition.json) — ID, SHA-256, размер
  и длительность аудио, агрегаты;
- [human_confirmation.json](reports/voice_test/human_confirmation.json) — подтверждения людей.

Текстов, их контрольных сумм, имён и меток по отдельным записям в Git нет.

## Повторная проверка

Нужны `av`, `numpy` и `pytest` из [requirements.txt](requirements.txt).
Whisper и модели не загружаются.

```bash
python tools/validate_voice_test.py          # UNCHANGED и код 0, если набор не менялся
python -m pytest -q tests/test_validate_voice_test.py
```

Валидатор полностью декодирует каждый файл через PyAV. Он проверяет:

- ровно 36 обычных файлов `voice_001–voice_036` без лишних элементов
  (каталог или ссылка на месте файла — ошибка);
- совпадение ID и порядка строк на обоих листах, формат ID `voice_NNN`;
- контейнер ogg/opus;
- лимиты голоса из `configs/resource_check.json` (30 s, 5 242 880 B);
  размер проверяется до декодирования;
- отсутствие пустых файлов и побайтовых дублей;
- непустые и уникальные эталоны, целое число в столбце «Слов»;
- две метки из `negative/neutral/positive` и согласованную метку;
- обязательную отметку спора при несовпадении меток;
- отметки сверки и подтверждения человеком;
- распределение 12/12/12 и не меньше трёх дикторов среди полностью проверенных записей;
- отсутствие совпадений с SHA-256 отладочного аудио и текста T08
  (без `reports/speech/verification.json` проверка завершается ошибкой).

Данные валидатор не исправляет: при любом нарушении он перечисляет ошибки
и завершается с кодом 1. Повреждённая таблица — тоже ошибка с кодом 1.
В сообщениях указываются ID записи или номер строки и название поля;
значения ячеек, тексты и имена не выводятся.

Без `--write` валидатор сравнивает пересобранный набор с сохранёнными файлами:

- в манифесте проверяются обязательные поля, `content_sha256` пересчитывается
  по его записям, и каждое поле каждой записи сравнивается с проверенными данными;
- отчёт сравнивается полностью, и его `content_sha256` должен совпадать с манифестом.

Допустимые различия только такие: `audio_path` в манифесте (расположение
копии) и даты `frozen_at`/`rebuilt_at` в отчёте. Повреждённый или неполный
манифест или отчёт даёт `CHANGED` и код 1. То же для JSON, который
не является объектом нужной структуры: `null`, массив, строка, число.

`--write` создаёт фиксацию только один раз, когда нет ни манифеста, ни отчёта.
Если фиксация уже есть и совпадает с данными, команда выводит `ALREADY_FROZEN`
и ничего не меняет. Если фиксация есть и отличается, либо есть только один
из двух файлов, команда отказывает с кодом 1, файлы не изменяются. Заменить
существующую фиксацию этим инструментом нельзя: изменение состава возможно
только по отдельному решению команды, до получения любых предсказаний.

Каждый файл сначала полностью пишется во временный `.<имя>.tmp` рядом с целью
и появляется под своим именем жёсткой ссылкой, которая не перезаписывает
существующий файл. При ошибке записи, закрытия или создания ссылки свои
временные файлы и уже созданный первый файл удаляются. Чужой временный файл
с тем же именем не трогается, запись в этом случае отклоняется.

Два файла при этом не появляются одним атомарным шагом. При аварийном
завершении процесса между двумя ссылками может остаться только манифест:
валидатор определит это как неполную фиксацию и откажет. При аварии во время
записи может остаться временный файл: следующий `--write` откажет из-за него.
В обоих случаях лишние файлы удаляются вручную после проверки. Для `--write`
файловая система должна поддерживать жёсткие ссылки.

## Фиксация

Набор зафиксирован **15.11.2026**: в этот день окончательные файлы переданы
на проверку и впервые записан манифест. Таблица последний раз сохранена
2026-11-15T15:36:22Z.

Манифест пересобран в тот же день (`rebuilt_at`) по двум причинам: добавлены ID
разметчиков R01/R02, а SHA-256 транскрипций убраны из публичного отчёта.
Аудио, транскрипции и метки не менялись. Поэтому `content_sha256` сменилась
с `81620fde…4481c` на текущую. Тогда `--write` ещё допускал пересборку;
теперь существующая фиксация не заменяется.

| Показатель | Значение |
|---|---|
| Записей / дикторов / разметчиков | 36 / 4, по 9 на диктора / 2 (`R01`, `R02`) |
| Согласованные метки | 12 negative, 12 neutral, 12 positive |
| Метки R01 и R02 | по 12/12/12 каждая; совпали в 36 из 36; споров 0 |
| Неоднозначных | 0 |
| С бытовым шумом | 5 (negative 1, neutral 2, positive 2) |
| Формат | OGG/Opus, mono, 48 kHz, все 36 декодируются полностью |
| Длительность | 8.1–15.5 s, медиана 12.1 s, всего 431.8 s |
| Размер | 40 053–75 887 B |
| SHA-256 таблицы | `b6d2ce446c2b3db9702a949831b7985270117be82189dd7a44eeb4f1a62811e3` |
| `content_sha256` манифеста | `4004319e4f5b728b7edb006a4ca717bfd5a16bfa864709d34ca8f0fe1943c8c6` |

SHA-256 всех 36 аудиофайлов — в `records` отчёта.

Набор считается неизменным, если выполнены все условия:

- 36 SHA-256 аудио и `content_sha256` совпадают с отчётом;
- `python tools/validate_voice_test.py` возвращает код 0;
- после получения предсказаний состав и метки не менялись.

Если таблица пересохранена без изменения содержимого, валидатор сообщит
о другом SHA-256 таблицы (`source_xlsx_sha256`). В этом случае нужно сверить
таблицу с зафиксированной версией; заменить фиксацию валидатор не позволит.

## Что проверено технически и что подтверждено людьми

Технически, по файлам:

- формат, декодирование, размер, длительность и уникальность аудио;
- полнота таблицы, распределение классов и отметки шума;
- совпадение сумм с контрольным списком передачи.

Однократно сравнены 36 эталонов с текстами train/validation/test из `NLP_dataset/`
по словным 5-граммам: ни одна запись не делит с каким-либо отзывом
больше 6 % своих 5-грамм.

Подтверждено пользователем, по файлам не проверяемо:

- записи сделаны реальными людьми, синтез речи не применялся;
- все эталоны сверены прослушиванием и дословно совпадают со сценариями;
- разметку выполнили два независимых человека, не являющиеся дикторами;
- все члены команды имеют доступ к закрытой папке.

Права доступа к облачному хранилищу технически не проверялись.

Известные ограничения:

- у 9 записей одного диктора кодировщик FFmpeg (после конвертации),
  у остальных libopus;
- в трёх файлах есть 6–17 сэмплов на уровне клиппинга; записи не исключались;
- отладочные транскрипции T08 доступны только как SHA-256, поэтому их
  близкие перефразы не проверялись.
