## Объём сдачи

Система классифицирует текстовые киноотзывы из Telegram как negative, neutral
или positive. Для этого этапа используем **TF-IDF + Logistic Regression**.
Классы соответствуют ранее предоставленному описанию кейса; актуальная ссылка
на таблицу кейсов при проверке не открылась. Соответствие метода содержанию
вебинара 4 нужно сверить по его материалам, которых пока нет в репозитории.

Обязательный результат: описание данных и их качества, реализованная
предобработка, классификация без трансформеров, анализ неверных предсказаний,
обоснование метода и короткий открытый отчёт со ссылкой на репозиторий.
Работу с Telegram показываем сначала через текстовый режим существующего бота.

RuBERT, ансамбль, TTS, класс noise, перенос на другие темы и презентация
не входят в обязательный объём этой промежуточной сдачи. RuBERT остаётся
в полном исследовательском плане. Ансамбль может дать дополнительные 5 баллов,
но не должен задерживать основные пункты. Whisper относится к распознаванию
речи: если голосовая часть включена в отчёт, её явно отделяем от классификатора
без трансформеров. Текстовый режим не требует Whisper.

## Критерии задания и необходимые результаты

| Пункт | Результат этапа |
|---|---|
| Покрытие и состав данных | Источник, лицензия, поля, языки, размеры до/после очистки, распределения классов и независимость сплитов |
| Качество, нормализация, шум/чистые сегменты | Проверяемые определения дефектов, количества и доли с явными знаменателями; ограничения смысловой разметки |
| Качество транскрипций | Для письменного корпуса — неприменимо; для отдельной отладочной речи — аудиопараметры, проверенный эталон и WER с ограничениями малого набора |
| Предобработка — 5 баллов | Отбор языка и дедупликация; описание фактической обработки TF-IDF. Нормализация ключа дубликатов не выдаётся за изменение входного текста модели |
| Классификация — до 10 баллов | TF-IDF + Logistic Regression, воспроизводимые настройки, accuracy и дополнительные метрики классов |
| Обработка после классификации — 10 баллов | Матрица ошибок и объяснения 30–50 реальных неверных предсказаний; это рабочая трактовка неоднозначного пункта, не подтверждение преподавателя |
| Обоснование метода — 5 баллов | Связь с задачей, ограничения корпуса, работа на CPU, отсутствие трансформеров, воспроизводимость |
| Приём работы | Файл короткого отчёта открыт без авторизации, в нём есть ссылка на репозиторий; ссылка прикреплена в ЛМС |

Доля исключённых дубликатов не равна доле всех шумных примеров. Neutral не
является шумом. Аудит 100 сбалансированно выбранных строк не даёт оценки доли
ошибок во всём корпусе. Для исходных письменных отзывов продолжительность,
аудиопараметры и качество транскрипций неприменимы; их не следует выдумывать.
Если измеряем ASR на отладочном аудио, не используем финальные 36 записей и не
выдаём один короткий фрагмент за оценку качества на всех сообщениях Telegram.

## Метрики и сохранение финального test

В сохранённом Windows-запуске C=2: **validation accuracy 89,024625%**,
macro-F1 0,72249892, F1 neutral 0,351706. Источник:
[validation_results.csv](../reports/baseline/validation_results.csv).
Это результаты конкретного запуска, не гарантия оценки и не метрики независимого test.
У Mac другой результат; нельзя брать модель одного запуска и числа другого.

Шкала задания для accuracy: ≥90% — 10 баллов; ≥85% — 8; ≥80% — 5; ≥75% — 3.
Macro-F1 не подставляем вместо accuracy. Сохраняем обе метрики, поскольку
преобладающий positive скрывает слабое качество neutral в общей accuracy.

Для промежуточного отчёта используем полную **validation**, прямо указывая,
что по ней уже выбирали C. После фиксации комплекта сохраняем предсказания,
метрики и разбираем ошибки. Параметры этой сдачи по просмотренным ошибкам
не подгоняем. Аудит исходных меток T02 не заменяет анализа ошибок модели.

**Финальный test остаётся закрытым** до фиксации полного эксперимента T12 (#15).
Это уточняет ранее предложенный порядок сдачи: ранний разбор test-ошибок
создаст риск подстройки будущего RuBERT, который ещё не обучен. Validation
не называем независимой итоговой оценкой. В тексте задания отдельный test
явно не предписан; принятие такой оценки преподавателем не гарантировано.
Если отдельный test потребуется, сначала меняем протокол: фиксируем обе модели
до открытия либо резервируем отдельный нетронутый набор для будущего сравнения.
Просмотренный test не объявляем повторно слепым.
