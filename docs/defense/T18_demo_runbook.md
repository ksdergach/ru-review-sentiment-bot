# T18: сценарий живой демонстрации и резервного видео

Практическая инструкция для показа Telegram-бота на защите. **Основная конфигурация —
принятый baseline (TF-IDF + LR) и Whisper.** Ручные прогоны T09 и T16 выполнялись с RuBERT,
поэтому показ именно с baseline нужно проверить заново на машине защиты — прежние протоколы
этого не подтверждают.

**Статус на момент подготовки (22.11.2026): живая проверка не выполнена.** У агента нет доступа
к Telegram, моделям и машине защиты. Разделы 1–4 выполняет команда; результат записывается
в [шаблон репетиции](T18_rehearsal.md).

Запуск и ограничения бота подробно описаны в [README, раздел T09](../../README.md#голосовой-telegram-бот-t09).

## 0. Правила

- Токен вводится только скрыто и только в окружение процесса. Не показывать на экране и не записывать
  токен, `env`, историю команд, имена пользователей Telegram, чужие чаты и уведомления.
- **Не использовать 36 записей T11** и их тексты: это независимый тест, а не источник удачных примеров.
  Не брать тексты из train и validation.
- Демонстрационные отзывы — новые записи команды. Они проверяют работу сценария, а не качество модели:
  не включать их в метрики, не дообучать и не настраивать по ним модель.
- Аудио, тексты демонстрационных отзывов и видео хранить **вне Git**.
- Не обещать конкретную метку заранее. Говорить: «посмотрим, что ответит модель».
- Заранее записанное видео — резерв. Если показываем его, прямо говорим, что это запись, и называем её дату.

## 1. Подготовка демонстрационных примеров (за 1–3 дня)

1. Составить 3 коротких новых киноотзыва (10–20 секунд): явно положительный, явно отрицательный
   и один смешанный или нейтральный. Не копировать отзывы из корпуса.
2. Записать каждый голосовым сообщением Telegram и сохранить в «Избранном»: так сообщение можно
   переслать боту, если живая запись в аудитории не получится.
3. Подготовить отказной пример: голосовое сообщение длиной 35–40 секунд. Если в аудитории шумно —
   текст длиннее 2 000 символов. Текст должен быть вашим, а не из датасета.
4. На машине защиты отправить каждый пример боту с baseline и записать в журнал вне Git:
   дату, backend, полученную метку и уверенность. Для показа выбрать примеры, ответ на которые
   проверен. Если ответ не совпал с ожиданием, пример не «подгонять». Либо заменить его другой
   новой записью, либо показать как честный пример ошибки модели.

## 2. Проверка готовности (в день защиты, за 30–60 минут)

Все команды — из корня репозитория в окружении из `requirements.txt` (проверенная среда:
Python 3.13.7, macOS arm64).

| # | Проверка | Команда / действие | Ожидаемый результат | Если не так |
|---|---|---|---|---|
| 1 | Версия кода | `git status`, `git log -1 --oneline` | Чистое дерево, известный коммит `master` | Переключиться на `master`, не править код перед защитой |
| 2 | Окружение | `python tools/check_environment.py` | `status: PASS` | Переустановить по [README](../../README.md#установка); при нехватке времени — резервное видео |
| 3 | Комплект baseline | `python -c "import hashlib; print(hashlib.sha256(open('models/nlp_baseline/tfidf_logreg_baseline.joblib','rb').read()).hexdigest())"` | `389a768bcd108721c79ebf3a7b9dc5212ec100f5c2e1b06cf519ed076cd9bee3` | Получить принятый файл у участника команды. **Не переобучать локально** |
| 4 | Тест принятого baseline | `python -m pytest -q tests/test_classifier_accepted_baseline.py` | `passed`, без `skipped` | Проверить путь и сумму комплекта (п. 3) |
| 5 | Классификатор | `CLASSIFIER_BACKEND=baseline python tools/predict_text.py "<своя короткая фраза о фильме>"` | JSON с `label`, `confidence`, `probabilities` | Проверить переменную `CLASSIFIER_BACKEND` и комплект |
| 6 | Whisper из локального кэша | `python -m src.speech <путь к демонстрационной записи вне Git>` (без `--allow-download` модель берётся только из кэша) | JSON с `"status": "ok"` и `"error_code": null` | Один раз загрузить модель по README (`--allow-download`) с отдельной отладочной записью, не T11 |
| 7 | Интернет и Telegram | Открыть Telegram Desktop или телефон с выводом экрана; проверить сеть в аудитории | Чат с ботом открывается | Мобильный интернет; при недоступности Telegram — резервное видео |
| 8 | Звук и экран | Проверить микрофон, громкость, видимость чата на проекторе, крупный шрифт Telegram | Голосовое записывается, текст читается с последнего ряда | Переслать заранее записанное голосовое из «Избранного» |
| 9 | Отвлекающие данные | Включить «Не беспокоить», закрыть посторонние чаты и окна | На экране только чат с ботом и презентация | — |

Запуск бота (один процесс polling на токен; терминал не закрывать до конца показа):

```bash
read -rs TELEGRAM_BOT_TOKEN && export TELEGRAM_BOT_TOKEN   # ввод не отображается
export CLASSIFIER_BACKEND=baseline
python -m src.bot
```

PowerShell 7: `$env:TELEGRAM_BOT_TOKEN = Read-Host -MaskInput`, затем
`$env:CLASSIFIER_BACKEND="baseline"` и `python -m src.bot`.

Ожидается строка `Loading classifier and Whisper models` и **отсутствие** `Startup failed`.
Модели загружаются до подключения к Telegram, поэтому первый ответ может прийти не сразу после запуска.
Терминал с журналом не выводить на проектор.

Контрольный прогон: `/start`, затем один демонстрационный голосовой отзыв. Ответ должен прийти;
по замеру T14 распознавание одной записи 8–16 секунд занимало в среднем около 4 секунд на Apple M1.

## 3. Основной показ (~3 минуты)

| Шаг | Действие | Ожидаемое поведение | Как проверить | Запасной вариант |
|---|---|---|---|---|
| 1 | Коротко представить бота и отправить `/start` | Назначение, три класса, лимиты: голос до 30 с и 5 МиБ, текст до 2000 символов | Ответ пришёл за несколько секунд | Показать слайд 11. Если бот молчит — проверить терминал (процесс жив, нет `Startup failed`) и перезапустить |
| 2 | Записать голосовой киноотзыв (или переслать заранее записанный из «Избранного») | Бот принимает сообщение. Пока идёт обработка, другие отзывы получают просьбу повторить позже | Нет сообщения об ошибке | Переслать проверенную запись; при повторном сбое — резервное видео |
| 3 | Показать транскрипцию | Блок «Распознанный текст:» с текстом Whisper | Текст близок к сказанному, возможны ошибки слов | Пояснить: ошибки слов ожидаемы, WER в T14 — 0,1569 |
| 4 | Показать тональность | «Тональность: … (negative / neutral / positive)» и «Уверенность модели: …%» | Метка — одна из трёх, есть оговорка об уверенности | Если метка неожиданная, не спорить с моделью: это наблюдение, а не оценка. Сослаться на результаты T14/T15 |
| 5 | Вспомогательный текстовый режим: скопировать распознанный текст и отправить обычным сообщением | Та же метка, что у голосового ответа (один классификатор) | Метки совпадают | Отправить заранее подготовленный короткий текстовый отзыв |
| 6 | Отказ: голосовое на 35–40 с (или текст длиннее 2 000 символов) | «Голосовое сообщение слишком длинное. Максимум — 30 секунд.» (для текста: «Сообщение слишком длинное. Максимум — 2000 символов.») | Метки нет, сообщение понятное | Показать строку таблицы ограничений на слайде 11 |

После показа вернуться к слайду 12. Если использовано резервное видео, сказать об этом прямо.

## 4. Резервное видео

Видео — подстраховка на случай сбоя сети, Telegram или машины. Оно должно показывать
**фактическую работу бота**: не слайд-шоу, не имитацию интерфейса и не монтаж ответов.

### Сценарий записи (2–3 минуты, одним дублем или с минимальными склейками)

| Кадр | Что показать | Не показывать |
|---|---|---|
| 1 | Подпись «Запись демонстрации от <дата>, backend baseline» (титр или файл с этим названием) | — |
| 2 | Чат с ботом: `/start` и ответ | Имя аккаунта, аватар, список чатов, уведомления |
| 3 | Отправка голосового киноотзыва и ответ: транскрипция, тональность, уверенность | Номер телефона, другие чаты |
| 4 | Тот же текст обычным сообщением и совпадающая метка | — |
| 5 | Голосовое длиннее 30 с и отказ без метки | — |
| 6 (по желанию) | Терминал с запущенным `python -m src.bot` без токена и переменных | Ввод токена, `env`, история команд, домашний путь с личным именем |

Рекомендации: запись экрана в 1080p со звуком (голос диктора нужен, чтобы было слышно отзыв),
формат MP4 (H.264 + AAC). Перед записью включить «Не беспокоить», крупный шрифт Telegram.
После записи просмотреть видео целиком и вырезать кадры с личными данными.

### Проверка воспроизведения

1. Открыть файл на машине защиты **и** на другом устройстве: видео, звук, длительность, без чёрных кадров.
2. Убедиться, что файл открывается без интернета (локальная копия на машине защиты).
3. Проверить, что все участники имеют доступ к хранилищу.

### Где хранится (заполняет команда, вне Git)

| Поле | Значение |
|---|---|
| Доступный команде путь или ссылка на видео | _заполнить_ |
| Локальная копия на машине защиты | _заполнить_ |
| Дата записи, коммит, backend | _заполнить_ |
| Длительность, формат | _заполнить_ |
| Проверил воспроизведение (роль, дата) | _заполнить_ |

Критерий «резервное видео доступно команде вне Git» остаётся открытым, пока таблица не заполнена
по фактической записи.
