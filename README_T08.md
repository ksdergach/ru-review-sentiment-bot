# T08 — распознавание русского голоса

`src/speech.py` преобразует локальный аудиофайл, в том числе Telegram OGG/Opus,
в полный русский текст. PyAV декодирует файл в mono float32 / 16 kHz;
Whisper обрабатывает этот массив. Отдельный системный FFmpeg для модуля не нужен.

## Выбранная конфигурация

[configs/speech.json](configs/speech.json): `Systran/faster-whisper-small`,
ревизия `536b0662742c02347bc0e980a01041f333bce120`, CPU / int8, 8 потоков,
beam_size=5, language=ru, VAD включён, temperature=0,
condition_on_previous_text=true. Путь к кэшу — относительно корня проекта.

Модель, точность, число потоков, beam и VAD взяты из прошедшего
[профиля T05 primary](reports/resources/primary/resource_summary.md).
В T08 зафиксированы также ревизия и параметры декодирования. Это рабочая
конфигурация для дальнейшей фиксации в T12, а не результат подбора на финальном
аудиотесте. T05 показывает доступность ресурсов на машине команды; локальный
прогон T08 дополнительно проверяет новый модуль на macOS.

## Запуск

Используйте [окружение проекта](README.md). Все команды ниже — из корня репозитория.
Первый запуск с разрешённым скачиванием весов:

```bash
python -m src.speech artifacts/audio/debug.ogg --allow-download --show-text
```

Замените путь на собственную отладочную запись. Веса скачиваются из Hugging Face
в игнорируемую `.cache/huggingface/`. Аудио распознаётся локально, на сервер
не отправляется. На проверенной установке macOS при ошибке доверия сертификату
потребовалась переменная `SSL_CERT_FILE=/etc/ssl/cert.pem`; проверка TLS остаётся включённой.

Дальнейшие запуски по умолчанию используют только локальные веса:

```bash
python -m src.speech artifacts/audio/debug.ogg --show-text
```

Без `--show-text` выводятся статус, длительность, число сегментов и символов,
время обработки и загрузки модели, но не сама транскрипция. Код возврата:
0 для `ok`/`empty`, 1 для технической ошибки, 2 для ошибки аргументов/конфига.

## Контракт для бота

```python
from src.speech import SpeechRecognizer

speech = SpeechRecognizer()  # Один экземпляр на всё приложение.

async def handle_local_voice(path):
    result = await speech.transcribe_async(path)
    if result.status == "ok":
        return result.text  # Только этот текст передавать классификатору.
    if result.status == "empty":
        return "Не удалось разобрать речь. Попробуйте записать сообщение ещё раз."
    return "Не удалось обработать аудио. Попробуйте ещё раз."
```

`SpeechResult` содержит:

| Поле | Значение |
|---|---|
| `status` | `ok`, `empty` или `error` |
| `text` | Полный текст; пустая строка при `empty`/`error` |
| `error_code` | `file_not_found`, `decode_failed`, `model_load_failed`, `inference_failed`; иначе `None` |
| `duration_seconds` | Длительность декодированного аудио; `None`, если декодирование не удалось |
| `elapsed_seconds` | Полный проход: декодирование, первая загрузка модели, все сегменты; без ожидания блокировки |
| `model_load_seconds` | Время загрузки в этом вызове; 0 при повторном использовании модели |
| `segment_count` | Число полностью прочитанных сегментов; 0 при ошибке |

Пустая речь не становится neutral или noise. Ошибка в середине генератора
отбрасывает частичный текст, чтобы он не попал в классификатор как успешный ответ.
Исключения библиотек и локальные пути не передаются пользователю в результате.

Модель загружается при первом корректно декодированном непустом аудио и затем
переиспользуется. Ошибка загрузки возвращает `model_load_failed`; следующий вызов
может повторить загрузку после устранения причины. Обычные запросы не скачивают
веса: подготовьте кэш до запуска бота.

`transcribe()` — синхронный метод для CLI/рабочего потока. В async-обработчике
нужно вызывать `transcribe_async()`: и декодирование, и загрузка, и **весь ленивый
генератор сегментов** выполняются внутри `asyncio.to_thread`. Блокировка защищает
единственную модель от параллельной инициализации и сериализует обращения.

## Временные файлы и отмена

Бот владеет своим временным файлом: создаёт уникальный путь, передаёт его модулю
и удаляет в `finally` после завершения `await speech.transcribe_async(path)`.
Модуль не создаёт промежуточных аудиофайлов и не удаляет входной файл.

Отмена async-вызова дожидается окончания рабочего потока, затем передаёт
`CancelledError` вызывающему коду. Поэтому его `finally` не удалит аудио раньше
времени. Повторная отмена также проверена тестом. Поток Python нельзя безопасно
оборвать посередине инференса: `asyncio.wait_for` здесь **не даёт жёсткого таймаута**.
Лимиты размера/длительности, отказ «занят», ограничение очереди и решение для
жёсткого таймаута относятся к T10; интеграция с Telegram — к T09.

## Проверки

Автоматические тесты без скачивания весов:

```bash
python -m pytest -q tests/test_speech.py
```

Реальная проверка выбранной модели на отдельном отладочном аудио:

```bash
python tools/verify_speech.py --audio artifacts/audio/debug.ogg --confirm-debug-audio
```

При пустом кэше можно добавить `--allow-download`. Команда выполняет холодный
и повторный проход одной записью на одной модели, затем проверяет сгенерированную
тишину и заведомо повреждённый файл. Тексты остаются в
`artifacts/speech/transcripts.json`; в Git сохраняются только агрегаты, SHA-256,
конфиг и окружение в `reports/speech/verification.json`.
Повторный запуск обновляет этот отчёт — проверяйте diff перед коммитом.

Фактическое происхождение использованного отладочного аудио, результаты и
ограничения проверки записаны в [reports/speech/verification.md](reports/speech/verification.md).
Это проверка работы ASR, не оценка WER или качества тональности. Финальные
36 голосовых отзывов и текстовый test в T08 не использовались.
