## Неизменяемые входы

Основа приложения: commit `5f22d93a8cff63b30fc129bb68a1cfbd4230995d` (master после PR42).
Это идентификатор кода приложения, а не будущего коммита самого документа.
`freeze.json: file_sha256` содержит суммы исходников `src`, конфигов, принятых
отчётов, ID и используемых служебных инструментов. При оценке отдельно записывается
фактический commit оценщика, происходящий от этой основы; зафиксированные файлы
должны совпадать. Несовпадение требует разбора до запуска, а не молчаливого обновления сумм.

Комплект RuBERT фиксируется всеми семью файлами и SHA-256 в
`models.rubert.bundle_files_sha256`. Исходная модель:
`cointegrated/rubert-tiny2`, revision `e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae`.
Содержимое `configs/transformer.json` совпало с JSON конфигурации внутри комплекта;
различия байтовых сумм этих двух файлов обусловлены сериализацией.

Whisper: `Systran/faster-whisper-small`, revision
`536b0662742c02347bc0e980a01041f333bce120`. Четыре локальных файла закреплены
суммами в `speech.bundle_files`. Параметры из `configs/speech.json`: CPU, int8,
8 потоков, русский язык, beam_size=5, VAD=true, temperature=0,
condition_on_previous_text=true. Сумма весов дополнительно совпала с проверкой T16;
остальные локальные суммы фиксируют эту копию, без заявления о повторной проверке
метаданных удалённого хранилища.

Baseline не получает дополнительной нормализации/усечения текста; применяется
сохранённый TF-IDF (word 1–2, lowercase и остальные параметры комплекта), LR C=2,
веса классов из train. RuBERT использует сохранённый токенизатор, max_length=64,
усечение справа. Нельзя менять правила, калибровку или пороги после test.
Классы неизменны: negative=0, neutral=1, positive=2.

## Текстовая оценка T13

1. После утверждения фиксации проверить суммы входов, чистоту отслеживаемых файлов,
   версию среды и commit оценщика. Использовать CPU; Torch — 2 потока, batch_size=64.
   Переменные окружения закреплены в `runtime_environment_variables`.
2. Через общий `src.classifier` проверить и загрузить оба комплекта. Для каждой
   модели один прогрев на трёх фиксированных `src.train_baseline._smoke_texts()`.
   Test не участвует в прогреве. Порядок измерений: baseline, затем RuBERT.
3. Один проход одинаковых 9 324 ID в порядке T03; `max_text_length=None` для обеих
   моделей. Лимит Telegram 2 000 символов здесь не отбрасывает длинные отзывы;
   внутреннее усечение RuBERT до 64 токенов сохраняется и учитывается в отчёте.
4. Macro-F1, accuracy, precision/recall/F1/support каждого класса, confusion matrix
   3×3: строки — эталон, столбцы — предсказание, порядок [0,1,2], zero_division=0.
   Отсутствующий в предсказаниях класс остаётся в среднем F1.
5. `perf_counter`: загрузка с проверкой комплекта, прогрев и основной проход отдельно.
   `ms_per_text = 1000 × inference_seconds / 9324`; указать размер батча и машину.
   Не выбирать самый быстрый повтор. Не выдавать время батча за задержку Telegram.
6. Основной test не менять. Отдельно показать чувствительность к повторам по принятому
   T03: одна первая по порядку test запись каждой группы точных/подтверждённых близких
   повторов; переиспользовать предсказания основного прохода без нового инференса.
7. Сохранить JSON/CSV, таблицу, графики и ID предсказаний без текстов. При неполном
   результате двух моделей не объявлять метрики финальными: сохранить причину,
   отдельно согласовать техническое исправление/повтор, не подбирать параметры.

Реализация подготовлена отдельно в [PR43](https://github.com/ksdergach/ru-review-sentiment-bot/pull/43),
прочитанный head `408895eb06d5322f7231fc15d7fde0358a835ea4`. Она ещё не входит в основу
этой фиксации и должна быть принята в T13. Формат JSON совместим с её минимальной
схемой; `draft-1` в имени схемы обозначает версию формата, а не статус утверждения.
Её `--check` не проверяет все расширенные
поля T12; перед реальным запуском необходима отдельная сверка сумм/окружения.

## Голосовая оценка T14

1. До старта проверить все 36 файлов/manifest, эталоны, комплекты и отладочное аудио.
   Ошибка предусловий останавливает запуск целиком, а не уменьшает набор.
2. Один выбранный baseline используется в обоих режимах: ручной эталон и результат
   Whisper. Порядок voice_001…voice_036, один последовательный проход, batch_size=1.
   Классификация через общий интерфейс, лимит 2 000 символов как у бота; превышение
   становится ошибкой записи, без скрытого усечения. WER-нормализация не применяется
   к входу классификатора.
3. Whisper декодирует через действующий `src.speech` в mono 16 kHz; без дополнительного
   шумоподавления. Непустые сегменты после strip соединяются одним пробелом.
   Загрузка/прогрев измеряются отдельно. Прогрев классификатора — те же три
   искусственных текста; ASR — один проход отдельной отладочной записи T16 с SHA-256
   `d6a29c51a3e22a08dafcbfdd045769bd4c6481f982e9ec03b7f91f382a0fa530`
   (204 813 байт). Этот файл предоставляется локально и не входит в T11/метрики.
4. Все 36 ID остаются в оценке. Пустой ASR/сбой дают служебное предсказание **-1**;
   это не новый обучаемый класс. Macro-F1 усредняется только по [0,1,2], ошибка
   даёт false negative истинному классу. Показывать 3×4 confusion matrix с отдельным
   столбцом ошибки, accuracy, классовые метрики, обе macro-F1 и Δ=(ASR − эталон).
5. WER использует существующие `tools.report_nlp_data_quality.words/word_error_rate`:
   Unicode NFC → casefold → пунктуация Unicode категории P заменяется пробелами →
   разделение по пробельным символам. **ё/е различаются; цифры остаются цифрами**,
   преобразования чисел в слова нет. Это правило одинаково для эталона и ASR.
6. Корпусный WER = сумма минимальных пословных замен/удалений/вставок по 36 ID,
   делённая на сумму слов эталонов; не среднее 36 WER. WER может превышать 100%.
   Пустой ASR/сбой распознавания — пустая гипотеза и удаление всех слов эталона.
   Сбой классификации при наличии расшифровки не обнуляет её для WER.
   Пустой эталон — ошибка предусловий. Отдельно считать пустые результаты,
   инфраструктурные ошибки и ошибки классификации с кодом причины.
7. На каждом ID через `perf_counter` измерять классификацию эталона, ASR (включая
   декодирование и полное чтение генератора), классификацию ASR и суммарный локальный
   ASR+classification. Telegram/передача по сети не входят. Сохранять время до отказа
   и статус для сбоев; агрегаты по всем 36 — сумма, медиана, p95 (linear).
   Успешные записи можно дополнительно описать отдельной подписанной статистикой.
8. Публичные результаты — ID, предсказания, статусы, тайминги и агрегаты; расшифровки
   остаются приватными. Проверки формул на искусственных данных должны подтвердить
   штраф за пустой ответ, правильный знаменатель WER и исключение -1 из среднего F1.

Размер 36, область кино и чтение сценариев ограничивают обобщение выводов.
Не исключать неудобные записи, не менять параметры и не добавлять новые попытки
распознавания ради улучшения метрик.

## Проверки и завершение фиксации

Результаты локальных технических проверок: [freeze_checks.json](freeze_checks.json).
Исходные отчёты T03/T11/N02/T06/T16 не заменены; модели и приватные данные игнорируются Git.

Команды подготовки/проверки, **не запускающие финальную оценку**:

```bash
.venv/bin/python tools/restore_frozen_test.py
.venv/bin/python tools/validate_voice_test.py
.venv/bin/python -m pytest -q -rs --tb=short tests/test_restore_frozen_test.py tests/test_classifier_accepted_baseline.py
```

Первая команда воспроизводит подготовленный Parquet из принятого исходника, не
перезаписывает другой существующий файл. При другой версии PyArrow байтовая сумма
может отличаться — зафиксированный test нельзя автоматически заменить.
Вторая команда требует уже подготовленный приватный manifest по README_T11;
обычная проверка не использует `--write` и не меняет принятую композицию.
Последняя команда использует синтетические данные и принятую validation, но не test/T11.

Полный протокол и исключения утверждены координатором 2026-11-19; публикация commit
и PR разрешена. Следующий этап завершения #15 — ревью и слияние PR с этой фиксацией.
Финальные запуски #16/#17 — следующие отдельные согласуемые шаги; их метрик пока нет.
