# T16: независимая установка и проверка Telegram-бота

**Статус: подготовлено, независимый запуск ещё не проведён.** Ниже — предварительная
проверка в изолированном Linux-окружении (её выполнил не независимый проверяющий) и
чек-лист для другого участника команды. Раздел «Результаты независимого запуска»
заполняется только по его фактическим наблюдениям. Задача:
[#14](https://github.com/ksdergach/ru-review-sentiment-bot/issues/14).

Проверяемый код — `master` `6ab27f0a7502db03f484bbb0d6a637663d698678` (после T10).
Изменения T16 затрагивают только документацию (`README.md`, `README_T06.md`, этот
протокол). Код, конфигурации и модели не менялись, переобучения не было.

В протокол не вносятся токены, идентификаторы Telegram, имена пользователей, IP-адреса,
адреса прокси, аудио и полные тексты отзывов. 36 финальных записей T11 (#13) не
используются ни здесь, ни в чек-листе.

## 3. Чек-лист для независимого проверяющего

Проверяет **другой участник команды** на своей машине или в своём окружении: свой
`git clone`, новое venv, модели скачиваются заново. Готовое окружение, каталоги
`models/` и `.cache/` автора не копировать.

Подготовьте заранее:

- Telegram-токен тестового бота. Для одного токена должен работать только один
  процесс polling. Токен задаётся только в переменной окружения текущей сессии.
- Две **свои отладочные** голосовые записи, не из T11: короткий киноотзыв
  (5–20 с) и любое сообщение длиннее 30 с (например, 35–40 с). Для загрузки
  Whisper (шаг 2) нужна та же короткая запись, сохранённая файлом, например
  `artifacts/audio/debug.ogg` (каталог игнорируется Git).

### Шаги

0. **Версия и среда.** Выполните `git clone`, `git checkout <SHA>` и `git rev-parse HEAD`
   по [README, «Установка»](../../README.md#установка). Запишите ОС, `python --version`, SHA.
1. **Установка** — по README, «Установка» (вариант PyTorch для вашей ОС), затем:
   `python -m pip check`, `python tools/check_environment.py`, `python -m pytest -q`.
   Ожидается: `No broken requirements found`; `"status": "PASS"` на Python 3.13.7
   (на 3.11/3.12 допустима единственная ошибка версии Python — запишите её);
   тесты без failed, допустим один skipped по принятому baseline.
2. **Модели.**
   - `python tools/fetch_transformer.py`, `python tools/restore_nlp_splits.py`,
     `python tools/verify_transformer.py` → «все 7 файлов совпали» и `"status": "passed"`.
   - `python -m src.speech artifacts/audio/debug.ogg --allow-download` → `"status": "ok"`.
   - Необязательно — SHA-256 `model.bin` в
     `.cache/huggingface/models--Systran--faster-whisper-small/snapshots/536b0662742c02347bc0e980a01041f333bce120/`
     (`shasum -a 256 model.bin` или PowerShell `Get-FileHash model.bin`): ожидается
     `3e305921506d8872816023e4c273e75d2419fb89b24da97b4fe7bce14170d671`.
3. **Запуск** — по README, раздел [«Голосовой Telegram-бот T09» → «Запуск»](../../README.md#запуск),
   с `CLASSIFIER_BACKEND=rubert`. Ожидается: в журнале нет `Startup failed`, бот отвечает
   на `/start`. Если бот не подключается к Telegram API (сетевые ошибки в журнале),
   запишите FAIL и тип ошибки без адресов. Код не меняйте; если без изменения не
   обойтись, опишите его в «Отклонения от README» (см. R1).

## 6. Ограничения

- Предварительная проверка выполнена на Python 3.12.3, а не на 3.13.7, без Telegram
  и без записи с речью; она не заменяет независимый запуск.

- Уверенность — оценка модели, а не гарантия правильности; качество модели по
  отладочным сообщениям не оценивается.
