> **Обновление 07.10.2026 (после приёмки T04/#6).** Диагноз ниже («Исследование
> расхождения») — подтверждённая неоднозначность отбора признаков в
> `CountVectorizer._limit_features`, способная изменять TF-IDF и ответы; `src/train_baseline.py`
> теперь разрешает такие равенства явным правилом (суммарная частота train по убыванию,
> затем строка Unicode по возрастанию), и два независимых запуска дают одинаковые словарь,
> IDF, коэффициенты и ответы. Это устраняет дефект для новых обучений, но **не доказывает**,
> что именно он был причиной исторического Windows/Mac-расхождения: исходный Windows-комплект
> недоступен, и ни одна из проверенных политик не воспроизвела его хеш — формулировка
> совпадает с выводом в [reports/baseline/reproducibility/README.md](../baseline/reproducibility/README.md#L36).
> T04/#6 закрыта по практическому решению (один воспроизводимый локальный комплект), а не
> по доказанной причине старого расхождения. Комплект N02 пересчитан на исправленном коде:
> `models/nlp_baseline/tfidf_logreg_baseline.joblib`,
> SHA-256 `389a768bcd108721c79ebf3a7b9dc5212ec100f5c2e1b06cf519ed076cd9bee3`,
> validation accuracy 88,9381%, macro-F1 0,718015 (см. [baseline_metrics.json](baseline_metrics.json)).
> Числа и хеши ниже относятся к более раннему, **уже не актуальному** комплекту и сохранены
> как ход расследования, а не как текущее состояние.

Для №25 использовался **Mac-комплект**, выбранный по согласованию с пользователем
07.10.2026, до исправления неоднозначности отбора признаков в #6 (не до доказательства
причины старого Windows/Mac-расхождения — она остаётся недоказанной, см. обновление выше).
Исходный Windows-комплект недоступен. Практическое решение для N02 тогда — зафиксировать
один локально воспроизводимый комплект и оценивать именно его; с исправлением #6 это
требование снято.

## Что проверено

Исходный код обучения T04 не менялся. В `configs/nlp_baseline.json` относительно
`configs/baseline.json` изменены только выходные каталоги:
`reports/nlp/training/` и `models/nlp_baseline/`. Все параметры сохранены:
seed=42, word TF-IDF с униграммами/биграммами, 100 000 признаков, min_df=2,
max_df=0.98, sublinear_tf, L2-нормировка; Logistic Regression, lbfgs,
C из [0.5, 1, 2], balanced-веса только по train, max_iter=1000, tol=1e-4.
В обоих новых запусках выиграл C=2, предупреждений о несходимости нет.
`src/text_preprocessing.py` не подключён к модели.

Код N02 закоммичен на ветке `issue-25-baseline-analysis`, смёрженной с `master` после
приёмки T04/#6 (коммит `838f550`); актуальная версия отчёта и чексумм — верхушка этой
ветки/[PR #28](https://github.com/ksdergach/ru-review-sentiment-bot/pull/28) (коммит
переписывался по ходу ревью несколько раз — конкретный SHA здесь не фиксируем, чтобы
не устаревал при каждой правке). Точные SHA-256 используемых файлов включены в
`baseline_metrics.json`. Это не тег сдачи nlp-v1; он относится к N04.

Подготовленные train/validation отсутствовали в рабочей папке. Они восстановлены
из исходных двух Parquet **по зафиксированным ID T03**, а не новым разбиением
или новым запуском дедупликации. `tools/restore_nlp_splits.py` проверяет принятые
манифесты, исходные суммы, порядок ID, метки, размеры и независимость train/validation.
Он не открывает исходный/подготовленный test. Восстановленные файлы побайтово
совпали с входами Windows-запуска:

| Данные | Строк | SHA-256 |
|---|---:|---|
| train | 76971 | `4889825b5bdc86c83ed69c7cdf3c4b073b9ebad36b2f6ca45b5204969422c675` |
| validation | 10396 | `f95a9223e216c4fe3be1e4a9a23a0dfd65ea81e8b37c0a680c0a4b1fe411c214` |

Окружение: Python 3.13.7, NumPy 2.3.3, pandas 2.3.2, scikit-learn 1.7.2,
SciPy 1.15.3, joblib 1.5.2, PyArrow 24.0.0; macOS arm64.
Параметры потоков обучения: OPENBLAS_NUM_THREADS=1, OMP_NUM_THREADS=1,
VECLIB_MAXIMUM_THREADS=1. Версии записаны и в модели, и в метаданных.

## Исследование расхождения

Код scikit-learn 1.7.2 в `CountVectorizer._limit_features` ограничивает словарь
через `(-tfs[mask]).argsort()[:limit]` без явного стабильного порядка равных частот.
Диагностика **только train** обнаружила 288 560 допустимых признаков:
91 032 встречаются чаще четырёх раз, 25 751 — ровно четыре раза.
На границе ограничения остаётся 8 968 мест, поэтому попадает только часть группы
с одинаковой частотой. [Числа](tfidf_boundary_diagnostic.json) воспроизводятся:

```bash
python tools/diagnose_nlp_tfidf.py
```

Это конкретный кандидат на источник различий словаря при разных реализациях
сортировки, **не доказанная причина исторического расхождения**. Различия
арифметики IDF также не исключены. Без Windows joblib нельзя отдельно сравнить
его vocabulary и IDF, а суммарный хеш этого не показывает. Настройки и алгоритм
обучения ради получения Windows-чисел не менялись.

Для полного расследования T04 потребуется исходный Windows joblib с SHA-256
`4f3d3cca2a1f7bdf98a8ba1baad783015e6375532c8df6227b62484db22185d4`,
затем сравнение словарей, индексов и IDF по совпавшим термам. Межплатформенная
идентичность нового обучения не заявляется. Для передачи команде нужен сохранённый
Mac-комплект вне Git вместе с конфигом и метаданными N02.

## Воспроизведение

В окружении `requirements.txt`, из корня проекта. Для существующего комплекта
**одна команда** пересчитывает все метрики, выбирает те же ошибки, проверяет
привязку аннотаций к предсказаниям и создаёт локальную страницу с полными текстами:

```bash
python tools/report_nlp_baseline.py
```

Файл `baseline_error_annotations.json` обязателен: при его отсутствии команда
завершается с ненулевым кодом до записи отчётов. Для первоначальной подготовки
выборки без аннотаций используется отдельный режим:

```bash
python tools/report_nlp_baseline.py --prepare-errors
```

Он сохраняет только `artifacts/nlp/baseline_error_selection.json` с выбранными
текстами и хешами для привязки будущего анализа. Итоговые отчёты и журнал ошибок
не перезаписываются; наличие этой выборки не подтверждает выполненный анализ.

На чистой рабочей копии сначала восстановить только train/validation:

```bash
python tools/restore_nlp_splits.py
```

Затем получить зафиксированный комплект и соответствующие метаданные N02 от
участника команды вне Git либо воспроизвести обучение на том же окружении Mac:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
  python src/train_baseline.py --config configs/nlp_baseline.json
python tools/report_nlp_baseline.py
```

Повтор обучения заменяет локальный комплект и `reports/nlp/training/`;
для проверки сдачи предпочтительна оценка сохранённого файла. При новом обучении
хеш joblib может измениться: скрипт связывает его с новыми метаданными и проверяет
метрики победителя. Аннотации принимаются только при совпадении полного вектора
предсказаний, выбранных ID, меток, хешей текстов и `model_state_sha256`.
Последний фиксирует словарь, IDF и параметры TF-IDF, mapping, порядок классов,
коэффициенты и свободные члены классификатора. Он не зависит от сжатия joblib
и размещения массива в памяти. Изменённые коэффициенты отклоняются даже при
совпадении всех предсказанных классов: прежние численные объяснения нельзя
переносить на другую модель. При несовпадении проверок отчёты не записываются.

После прочтения ошибок модель и гиперпараметры не менялись. Полные тексты
сохраняются только в игнорируемом `artifacts/nlp/`; модель — в `models/`.
Финальный test и финальные аудиозаписи не использованы. Человеческий просмотр
40 случаев ожидается и не приписывается пользователю.
