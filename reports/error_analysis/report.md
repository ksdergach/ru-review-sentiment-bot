## А. Текстовая классификация

### А.1. Ошибки baseline на test

Объект анализа — модель бота, выбранная в T12 по validation и ресурсам:
TF-IDF + Logistic Regression (`bot_model = baseline` в `reports/freeze.json` и
`final_metrics.json`; `bot_model_changed_by_test = false`). Ошибка — несовпадение
истинной метки и ответа модели в `reports/evaluation/predictions.csv`; SHA-256 файла и
пересчитанная матрица ошибок совпадают с T13.

Ошибок: **1 019 из 9 324** (10,93 %); accuracy 0,8907, macro-F1 0,7264.

| Истина → ответ | Ошибок | Доля ошибок | Разобрано |
|---|---:|---:|---:|
| negative → neutral | 149 | 14,6 % | 7 |
| positive → neutral | 273 | 26,8 % | 7 |
| neutral → negative | 110 | 10,8 % | 7 |
| neutral → positive | 119 | 11,7 % | 7 |
| negative → positive | 122 | 12,0 % | 6 |
| positive → negative | 246 | 24,1 % | 6 |
| **всего** | **1 019** | 100 % | **40** |

По истинному классу ошибок: negative 271, neutral 229, positive 519. По ответу модели:
negative 356, neutral 422, positive 241. Класс neutral участвует в **651 из 1 019 ошибок
(63,9 %)**, хотя составляет только 411 из 9 324 записей test (4,4 %).

### А.2. Правило отбора

Правило записано в коде до чтения текстов (`select_errors`) и не зависит от их содержания
и порядка строк:

1. Шесть направлений ошибок обходятся по очереди в порядке: negative→neutral,
   positive→neutral, neutral→negative, neutral→positive, negative→positive,
   positive→negative. Из каждого берётся следующий случай, пока не набрано 40.
2. Внутри направления порядок задаёт SHA-256 строки `42:<record_id>` (тот же ключ, что
   при разборе validation в N02); равенства решаются по ID.
3. Если ошибок меньше 40, берутся все; пустое направление пропускается.

Так как 40 = 6 · 6 + 4, четыре направления с участием neutral получают по 7 случаев,
два направления negative↔positive — по 6. Это сделано намеренно: Issue #18 требует
разобрать путаницу neutral. Выборка равномерна по направлениям и **не пропорциональна**
частотам ошибок. Поэтому доли категорий ниже описывают выборку и не переносятся на все
1 019 ошибок. В отличие от N02, четыре самых коротких текста отдельно не добавлялись.

Состав выборки: по истинному классу negative 13, neutral 14, positive 13; по ответу —
так же 13 / 14 / 13; с участием neutral — 28 из 40. `selected_ids_sha256` записан в
[text_summary.json](text_summary.json), полный список ID — в [text_errors.csv](text_errors.csv).
ID имеют вид `test-00000-of-00001.parquet#row=NNNNNNNN` (номер строки исходного Parquet).
Ниже для краткости указаны только последние восемь цифр, а «№» — позиция в выборке.
Повторить отбор: `python tools/analyze_errors_t15.py --check`.

### А.3. Категории

Категории — рабочая таксономия из Issue #18. У одного случая может быть несколько
категорий. `unknown` используется, только когда причина не установлена, и не сочетается
с другими категориями.

| Категория | Смысл | Соответствие N02 |
|---|---|---|
| `mixed` | В тексте есть и положительные, и отрицательные оценки | `mixed` |
| `unclear_label` | Исходная метка спорна по самому тексту; метка при этом не меняется | `unclear` |
| `sarcasm` | Ирония или сарказм | `sarcasm` |
| `short` | Короткий текст: не больше 15 слов и мало контекста | `short` |
| `neutral_confusion` | Граница с neutral размыта по правилам проекта: сдержанный итог, «на один раз», средняя оценка | `neutral` |
| `context` | Оценка относится не к фильму: к показу, другому фильму, книге, комментаторам. Либо текст вообще не отзыв | `context` |
| `negation` | Решающая оценка выражена отрицанием при оценочном слове | `negation` |
| `unknown` | Причина не установлена | — |

Количество в 40 разобранных случаях (категории пересекаются, сумма больше 40):

| Категория | Случаев | | Категория | Случаев |
|---|---:|---|---|---:|
| mixed | 21 | | negation | 7, из них 1 оспорен |
| context | 16 | | sarcasm | 3 |
| unclear_label | 11 | | short | 3 |
| neutral_confusion | 10 | | unknown | 1 |

Несколько категорий — у 27 случаев. Уверенность: high 5, medium 32, low 3. Уверенность
означает, насколько категории описывают сам текст. **Причинная связь с ответом модели
не проверялась ни в одном случае.** Модель на этих текстах не запускалась: веса признаков
и вклад слов не измерялись, поэтому формулировки о том, что повлияло на ответ, — гипотезы.

Счётчики даны по проверенной версии разметки. После проверки участником два значения
читаются с оговоркой (подробнее в [А.7](#а7-проверка-участником)):

- `negation` у №36 (`00003152`) оспорена проверкой и не считается установленной причиной ошибки;
- уверенность high у №11 (`00009138`) действует только с оговоркой о буквальном прочтении.

Разбивка категорий по направлениям ошибок есть в `text_summary.json`
(`categories_by_direction`). Кратко:

- **negative↔positive (12 случаев):** чаще всего mixed (7) и unclear_label (5). Сюда же
  попали оба случая sarcasm с противоположным классом и единственный `unknown`.
- **истинный neutral (14):** mixed 9, neutral_confusion 8, context 7.
- **ответ neutral при полярной метке (14):** context 6, mixed 5, unclear_label 5.

### А.4. Проблемы класса neutral

1. **Дисбаланс и слабое качество.** В test 411 нейтральных записей (4,4 %). Recall
   neutral 0,4428, precision 0,3013, F1 0,3586 — худший класс у обеих моделей.
   Ответ neutral дан 604 раза, из них 422 ошибочно; при этом 229 настоящих neutral
   пропущены. Крупнейшее направление ошибок — positive → neutral (273). Это всего 4,3 %
   positive-записей, но из-за преобладания positive в test даже малая доля даёт много
   ложных neutral.
2. **Neutral неоднороден по содержанию.** Среди 14 разобранных ошибок истинного neutral
   есть две разные группы:
   - Тексты **без оценки фильма**: обращения к другим комментаторам, просьба не писать
     спойлеры, анонс документального фильма (`00007783`, `00009141`, `00000686`,
     `00001577`). Метка neutral здесь соответствует правилам проекта, а модель выдаёт
     полярный класс. Гипотеза: на ответ влияет окрашенная лексика, не относящаяся к фильму.
   - **Смешанные отзывы без явного полярного итога** — 9 случаев (например, `00007103`,
     `00001023`, `00004160`, `00000942`, `00006679`). Модель выбирает полярный класс.
     Гипотеза: решает та часть текста, которая занимает больше места. По замечаниям
     участника к №9 и №35 объём критики или похвалы — наблюдение, а не установленная
     причина ответа. Итоговая рекомендация (№39) тоже не то же самое, что однозначный
     полярный вердикт.

   Это согласуется с наблюдением T02/N02: в исходном NEUTRAL встречаются и смешанные
   оценки, и обсуждения без оценки.
3. **Ответ neutral при полярной метке** часто приходится на тексты, где сама метка спорна.
   У 5 из 14 таких случаев отмечен `unclear_label`: `00007751`, `00003143`, `00005265`,
   `00009485` (positive → neutral) и `00005760` (negative → neutral: словесно отзыв
   отрицательный, но итоговая оценка средняя). В части этих случаев ответ модели
   по тексту объясним. Метки test при этом не исправлялись. По замечанию к №26
   (`00005265`) в объяснении нужно разделить три вещи: личное отношение автора,
   качество перевода и предположение о реакции других зрителей.
4. **Числовые итоги.** В трёх текстах есть явная числовая оценка: `00004160` — балл 3,
   `00005760` — 6 из 10, `00003152` — 8 из 10. В `00004160` шкала не названа. Правилами
   проекта не задано, какой балл соответствует neutral (замечание к №15), поэтому
   «средняя оценка» здесь — прочтение, а не правило. Модель мешка слов, вероятно,
   не учитывает такие числа как шкалу. Это гипотеза, она не проверялась.

### А.5. Содержание текста: характерные случаи

Ниже ID и краткие объяснения. Тексты здесь не приводятся, их можно открыть по ID
в исходном Parquet (см. [Д](#д-повторная-проверка-и-исправления)).

- **Смешанная оценка с отрицательным итогом → positive:** `00000581` — похвала
  визуальной части занимает больше места, чем отрицательный итог.
  **С положительным итогом → negative:** `00003152` — длинный список недостатков
  при итоговой оценке 8 из 10. Отрицание стоит только в заголовке списка недостатков,
  а решающий итог — числовой. Итоговая оценка «8 из 10» не подтверждает первоначальную
  трактовку, поэтому `negation` здесь оспорена проверкой и не считается установленной
  причиной ошибки (замечание к №36).
- **Возможная ирония:** `00009138` — рекомендацию посмотреть ради сравнения с книгой можно
  прочитать как ироничную, ответ positive. Буквальное прочтение не исключено (замечание
  к №11). `00008350` — ироничное перечисление штампов жанра.
- **Отрицание:** `00005423` — короткий отрицательный отзыв, где положительные слова
  относятся к общим предпочтениям, а оценка дана через отрицание. Ответ positive.
- **Объект оценки — не фильм:** `00008822` — похвала относится к книге, к экранизации
  отзыв однозначно отрицательный, ответ neutral. `00000297` — оговорка касается даты
  выхода в прокат, а не фильма. `00009268` (№32) — бо́льшая часть текста — рассуждение
  о религии. По замечанию к №32 короткие фразы о сильном впечатлении не являются однозначно
  положительной оценкой: сила впечатления не равна её знаку.
- **Спорная исходная метка:** `00005367` — отрицательная фраза обращена к определённой
  аудитории, а основная часть текста хвалит фильм. Ответ positive по содержанию выглядит
  обоснованным, но дефект разметки без правил аннотирования не установлен.
- **Причина не установлена:** `00007181` — короткий и для человека однозначно
  положительный текст получил negative.

Полный журнал — в [text_errors.csv](text_errors.csv).

### А.6. Вывод по тексту

Самые частые наблюдаемые свойства ошибок — смешанная оценка (21 из 40) и оценка, которая
относится не к фильму или вообще отсутствует (16). У 26 из 40 случаев есть хотя бы одна
из категорий mixed, neutral_confusion или unclear_label. Значит, заметная часть ошибок
связана с размытой границей классов и спорной разметкой, а не только со слабостью модели.
Сарказм, отрицание и короткие тексты встречаются реже. Отрицание как решающий признак
отмечено без замечаний в 6 случаях: в седьмом (№36) оно оспорено проверкой. Проверены все 40 случаев,
решений «не согласна» нет. Девять частичных согласий уточняют формулировки
причин. Категории не отменены, но `negation` у №36 не считается установленной причиной. Все выводы относятся к выборке,
отобранной поровну по направлениям.

### А.7. Проверка участником

Проверка проведена 22.11.2026 участником команды — Оксаной. Оксаной лично прочитаны все 40
отзывов, по каждому принято решение. Решения и сводка переданы координатором. Доказательство —
[human_review_evidence.json](human_review_evidence.json): 40 ID в порядке выборки,
`selected_ids_sha256`, `annotations_sha256` проверенной версии разметки и SHA-256
переданного файла решений. Инструмент `--check` принимает `confirmed` только при полном
совпадении этих сумм и решений.

| Решение | Случаев |
|---|---:|
| согласна (`agree`) | 31 |
| частично согласна (`partial`) | 9 |
| не согласна (`disagree`) | 0 |

`confirmed` означает, что человеческая проверка всех 40 случаев проведена. Безоговорочного
согласия со всеми объяснениями этот статус не означает. Проверка была не слепой: метки и
ответы модели были видны. Предложения и формулировки замечаний первоначально подготовил ИИ,
а приняты они участником после личного прочтения текстов. Самостоятельным авторским текстом
участника они не являются, и это не независимая проверка второго эксперта.

Содержание замечаний к частичным согласиям (без текстов отзывов). Они действуют как
ограничения интерпретации соответствующих объяснений:

| № | ID | Суть замечания |
|---:|---|---|
| 6 | `00008369` | Неточно указано, какую часть фильма хвалит автор. Исходная метка от этого не меняется |
| 9 | `00001023` | Объём критики — наблюдение, а не установленная причина ответа модели |
| 11 | `00009138` | Ироническое прочтение возможно, но высокая уверенность требует оговорки: допустимо и буквальное |

Сверка с исходными объяснениями (пометки при оформлении, `recorder_flags`):

- **№36 — категория `negation` оспорена.** Замечание противоречит присвоенной категории

  не считается установленной причиной ошибки. Повторная проверка не проводилась.

- Остальные замечания уточняют формулировки причин и уже совпадают с общей оговоркой
  «гипотеза, не проверено».

Исходные объяснения, категории, метки и предсказания T13 при оформлении проверки
не менялись: изменены только статусы проверки.

## Б. Влияние Whisper (T11, 36 голосовых записей)

### Б.1. Результаты T14 (контрольные значения)

Для каждой записи один и тот же baseline классифицировал эталонную транскрипцию и
результат Whisper. Значения ниже взяты из `reports/voice_eval/metrics.json` единственного
запуска T14. Это контрольные значения, а не результат нового эксперимента.

| Показатель | Эталонный текст | Whisper |
|---|---:|---:|
| macro-F1 | 0,8298931342 | 0,7018518519 |
| accuracy | 0,8333 (30 из 36) | 0,7222 (26 из 36) |
| F1 negative / neutral / positive | 0,7826 / 0,8182 / 0,8889 | 0,7500 / 0,5556 / 0,8000 |
| recall neutral | 0,75 (9 из 12) | 0,4167 (5 из 12) |

- ΔF1 = F1_ASR − F1_reference = **−0,1280412824**.
- Корпусный WER = (106 + 13 + 7) / 803 = 126 / 803 = **0,1569115816**.

### Б.4. Особенности класса neutral

- **Все пять смен ответа приходятся на истинный neutral.** У negative и positive ни один
  ответ не изменился: и верные, и ошибочные остались прежними.
- **Все четыре ухудшения — neutral.** Из 9 нейтральных записей, верных на эталоне, после
  Whisper полярный класс получили 4. Они уходят в обе стороны поровну: 2 в negative и
  2 в positive. Единого сдвига в одну полярность нет.
- **Пятая смена — тоже neutral:** ошибочный negative сменился ошибочным positive. Правильный
  ответ в этой записи не появился и не пропал, но ответ изменился.
- **Улучшений нет.** Ни одна из шести ошибок эталона не исправилась после Whisper.
- Отсюда падение recall neutral с 0,75 до 0,4167 и precision полярных классов. Всё
  снижение macro-F1 определяют пять смен ответа у нейтральных записей, прежде всего
  четыре ухудшения.

Возможное объяснение, согласующееся с текстовым анализом (А.4): у baseline класс neutral
опирается на слабые сигналы, и небольших изменений текста может хватать для полярного
ответа. Это **гипотеза, не проверенная причинным экспериментом**: признаки модели на этих
записях не измерялись, а на 12 нейтральных записях статистическая проверка невозможна.

### Б.5. Ошибки распознавания слов и ухудшение классификации

Это разные явления:

- **Ошибки слов распространены.** Корпусный WER T14 — 126 / 803 = 0,157: в среднем примерно
  каждое шестое слово эталона распознано с ошибкой.
- **Смена класса редка.** Ответ изменился у 5 записей из 36, ухудшился у 4, у 31 остался
  прежним.

Корпусный WER не говорит, ухудшится ли классификация конкретной записи. Эти данные не
устанавливают, какая ошибка слова вызвала смену ответа, и WER **не доказывает** причину
изменения предсказания. Для этого понадобился бы построчный разбор транскрипций, а в публичных
материалах его нет (Б.6). WER по группам записей не публикуется (Б.6), поэтому сравнение
групп в отчёте не приводится. Классификатор, его настройки и метки одинаковы в обоих режимах,
сбоев не было. Поэтому снижение ΔF1 = −0,128 связано с отличиями распознанного текста
от эталона. Какие именно отличия на него повлияли, не установлено.

### Б.6. Конфиденциальность и состав публичных агрегатов

**Уточнение способа выполнения Issue #18 (решение координатора от 21.11.2026).**
Issue требует сохранить ID и категории в `reports/`. Для голосового набора T11 индивидуальные
ID, предсказания и категории переходов хранятся только в закрытых материалах
`artifacts/t15/`. В Git попадают только безопасные агрегаты и интерпретации. Причина: вместе
с опубликованными матрицами T14 построчные данные позволяли бы восстановить эталонные метки
T11, как это уже было с первоначальным форматом T14 (вариант В1). Для текстового test
ID и категории публикуются полностью, как требует Issue.

Состав публичных агрегатов проверен в сочетании с уже опубликованными данными T14.
Учитывалась и первоначальная версия `predictions.csv` из PR #45, где есть предсказания
обоих режимов по каждому ID:

- **Метки отдельных записей.** По README_T14 из первоначального CSV вместе с двумя
  матрицами T14 выводились метки пяти записей. Расчёт показал, что эти данные уже
  однозначно задают полную таблицу «истинный класс × ответ на эталоне × ответ после
  Whisper». Переходы по классам и направления смены ответа выводятся из этой таблицы.
  Множество допустимых меток каждой записи до и после добавления агрегатов одно и то же:
  у 5 записей одна метка, у 16 — две, у 15 — три. Проверено перебором всех таблиц,
  совместимых с публичными данными. Печатались только эти счётчики, без ID и меток.
- **Групповой WER не публикуется.** По первоначальному CSV известен состав групп
  по смене ответа, а частично и по переходам. Поэтому любой WER по таким группам
  описывал бы конкретные записи. Например, если в группе нет записей без ошибок
  слов, это раскрывает признак каждой её записи. По решению координатора
  `wer_by_transition` и `wer_by_prediction_change` исключены из публичного файла
  (`withheld`). Полный результат хранится только в игнорируемом
  `artifacts/t15/voice_transitions_full.json`. Публичная детализация намеренно ограничена,
  чтобы защитить индивидуальные результаты. Публикуются переходы, разбивка по классам,
  направления смены ответа, сбои и контрольные значения T14, включая корпусный WER.
- **История.** Предыдущие коммиты PR #48 с групповым WER остаются в истории PR. Исправление
  текущей версии это раскрытие не отменяет.
- **Контрольная сумма полного файла не публикуется.** Скрытые значения малы, и при известной
  сумме их можно было бы подобрать перебором.

Публичный `voice_transitions.json` получен из полных агрегатов детерминированно:

```bash
python tools/analyze_voice_transitions_t15.py --from-full
```

Команда читает закрытый `artifacts/t15/voice_transitions_full.json` и не требует построчных
записей. Она сверяет агрегаты с `metrics.json` T14 (SHA-256, контрольные значения, границы,
суммы по классам, направления, суммы WER полного файла) и отклоняет неизвестные поля.
Публичное представление собирается явно по разрешённым полям.
Существующий файл не перезаписывается. Тест `test_published_voice_aggregates_agree_with_t14`
повторяет эту сверку для опубликованного файла.

Порядок полного пересчёта (только на машине измерений T14, где есть `artifacts/t14/records.json`):

1. Выполнить `python tools/analyze_voice_transitions_t15.py --check`. Ожидается код 0.
   Код 2 означает отказ: в этом случае ничего не исправлять и сообщить текст отказа
   без ID и меток.
2. Выполнить ту же команду без флага. Создаются закрытые `artifacts/t15/voice_transitions.json`
   (построчный журнал) и `artifacts/t15/voice_transitions_full.json`, а также публичный
   `reports/error_analysis/voice_transitions.json`.
3. Передать в Git **только** `reports/error_analysis/voice_transitions.json`. Каталог
   `artifacts/`, `records.json`, тексты, аудио и метки T11 не передаются ни в Git,
   ни в переписку.

## В. Ответы на исследовательские вопросы

**1. Даёт ли RuBERT преимущество перед baseline на зафиксированном текстовом test?**
Нет. На одном test из 9 324 записей (T13) baseline лучше RuBERT по всем основным метрикам:
macro-F1 0,7264 против 0,6803, accuracy 0,8907 против 0,8230. F1 каждого класса тоже
выше: negative 0,8822 / 0,8446, neutral 0,3586 / 0,2999, positive 0,9383 / 0,8964.
Ошибок у baseline 1 019, у RuBERT 1 650. Соотношение совпадает с validation
(0,7180 против 0,6678). RuBERT выдаёт neutral 1 436 раз при 411 нейтральных записях:
recall этого класса выше (0,674), precision намного ниже (0,193). Усечение до 64 токенов
затронуло 33,8 % текстов RuBERT. Это возможный, но не проверенный фактор. Вывод
относится к этому дообученному RuBERT, его настройкам и данному корпусу. Статистический
тест значимости разницы не проводился, а test не использовался для подбора моделей.
Проверенный участником разбор 40 ошибок baseline показывает, что слабое место обеих
моделей одно — класс neutral. Это и смешанные отзывы без полярного итога, и тексты
без оценки фильма, и спорные метки (А.4–А.7).

**2. Насколько ошибки Whisper изменяют качество классификации голосовых отзывов?**
На 36 записях T11 переход от эталонной транскрипции к Whisper снижает macro-F1
baseline на 0,128 (0,830 → 0,702), а верных ответов становится 26 вместо 30, при
корпусном WER 0,157. Сбоев и пустых ответов не было. Построчный расчёт показывает:
ухудшились 4 записи, улучшений нет, ещё у одной записи один ошибочный ответ сменился
другим. Все пять смен ответа — у истинного neutral. Ответы negative и positive ни разу
не изменились. Смена класса произошла у 5 из 12 нейтральных записей и у 5 из 36 в целом.
Возможное объяснение — изменения текста особенно влияют на слабые признаки neutral у baseline.
Это гипотеза, не проверенная причинным экспериментом. Причину отдельной смены по WER
установить нельзя. При 12 записях на класс и четырёх дикторах величины
неустойчивы: одна запись меняет accuracy на 2,8 п. п., а ΔF1 определяют пять записей.

## Г. Ограничения

- Текстовые отзывы — только о фильмах; на другие темы выводы не переносятся.
- Голосовой test — 36 записей (12 на класс), четыре диктора, чтение подготовленных
  сценариев, часть записей с бытовым шумом. Агрегаты не доказывают универсального
  эффекта Whisper.
- Класс neutral содержательно неоднороден: в нём есть и смешанные отзывы, и тексты
  без оценки фильма.
- Разобрано 40 из 1 019 ошибок. Выборка равномерна по направлениям, а не случайна
  и не пропорциональна. Частоты категорий не являются оценкой долей причин по всему test.
- Категории и объяснения — интерпретация текста, а не автоматически доказанная причина.
  Модель на разобранных текстах не запускалась, вклад слов не измерялся.
- Разметку подготовил ИИ-ассистент с видимыми метками и ответами модели, то есть
  не вслепую. Проверка проведена одним участником. Формулировки замечаний подготовил ИИ,
  а приняты они участником, так что это не независимая разметка второго эксперта. Девять случаев приняты
  частично. У №36 категория `negation` оспорена проверкой; разметка по решению
  координатора не изменена, а категория не считается установленной причиной.
- Подтверждающие документы. По тексту — решения участника и сводка, переданные
  координатором; суммы и полнота сверены инструментом. По голосу — полные агрегаты,
  посчитанные участником на машине измерений, и описание запуска (коды завершения,
  окружение). Здесь они проверены только по публичным данным T14. Построчные записи
  T14 для повторной сверки в публичных материалах недоступны, и так и должно быть.
  По публичным агрегатам нельзя удостоверить происхождение каждого отдельного счётчика WER:
  их согласованность с T14 проверена только по суммам.
- WER не устанавливает причину смены ответа. Групповой WER и построчный разбор транскрипций
  не публикуются.
- Интонация и акустические признаки эмоций не анализировались: классифицируется
  только текст.
- Финальный test нельзя использовать для настройки моделей. По этому анализу модели,
  пороги, предобработка, Whisper и метки не менялись и меняться не должны
  (`post_test_policy` в `reports/freeze.json`).

## Д. Повторная проверка и исправления

Проверка 40 случаев завершена (А.7). По решению координатора от 22.11.2026 разметка
по пометкам не исправлялась. Если позже будет решено её исправить (например, снять

   ```bash
   python tools/analyze_errors_t15.py --review-packet
   ```

3. Изменённые случаи подтверждаются участником. В `human_review_evidence.json` записываются

   ставится `confirmed`. Заполненный пакет содержит тексты и остаётся вне Git.

## Воспроизведение

Из корня репозитория в окружении `requirements.txt` (модели не нужны):

```bash
python tools/analyze_errors_t15.py --check
python -m pytest -q tests/test_analyze_errors_t15.py
```

Первая команда заново находит ошибки в `predictions.csv` и повторяет отбор. Затем она
сверяет разметку с выборкой и хешами текстов, проверяет доказательство проверки участником
и убеждается, что опубликованные файлы совпадают с пересчётом. Тесты дополнительно сверяют
`voice_transitions.json` с опубликованными результатами T14.
