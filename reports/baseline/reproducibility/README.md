# T04 — приёмка воспроизводимого baseline, 07.10.2026

**T04 принята.** Для следующих задач используется комплект
`models/baseline/tfidf_logreg_baseline.joblib`, обученный с однозначным правилом
отбора признаков. Актуальные метрики — в [validation_summary.md](../validation_summary.md)
и [winner_config.json](../winner_config.json).

## Что установлено

В прежнем пути scikit-learn 1.7.2 обрезает словарь до `max_features` по частоте,
применяя `argsort()` без стабильного разрешения равенств. NumPy не гарантирует
порядок равных значений при такой сортировке:
[документация argsort](https://numpy.org/doc/stable/reference/generated/numpy.argsort.html).
[Документация TF-IDF](https://scikit-learn.org/1.7/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)
описывает ограничение по частоте, но не задаёт правило равенств.

На тех же 76 971 train-строках после min_df/max_df:

- допустимы 288 560 признаков, лимит — 100 000;
- частота на границе — 4; выше границы — 91 032 признака;
- 25 751 признак делит оставшиеся 8 968 мест;
- смена quicksort на stable при одинаковых данных меняет состав словаря:
  симметрическая разность — 12 694 признака (6 347 замен);
- quicksort воспроизводит **точный прежний хеш TF-IDF на Mac**;
- stable с алфавитным исходным порядком воспроизводит хеш нового комплекта.

Доказательство: [feature_selection.json](feature_selection.json), команда:

```bash
python tools/diagnose_tfidf_selection.py
```

Скрипт читает только train и сохраняет агрегаты. Метрики классификатора не
использовались для выбора правила разрешения равенств.

**Предел вывода:** это подтверждённая неоднозначность отбора признаков, способная
изменять TF-IDF и ответы. Исходный Windows-комплект недоступен; ни одна из
проверенных здесь политик не воспроизвела его хеш. Поэтому точная причина
исторического Windows/Mac-расхождения не объявляется доказанной, а повторная
проверка новой процедуры на Windows не заявляется. Дефект устранён для новых
обучений; исторические результаты сохранены, для продолжения выбран один
воспроизводимый локальный комплект. Это решение заменяет прежнее ожидание
Windows-артефакта как блокер T04.

## Изменение процедуры

`fit_vectorizer_on_train` сначала считает целочисленные частоты словных n-грамм
через обычный CountVectorizer без max_features, но с прежними min_df/max_df.
Затем выбирает признаки по убыванию суммарной частоты; при равенстве — по
возрастанию строки Unicode, без зависимости от локали. Индексы выбранного
словаря тоже назначаются в порядке Unicode. Обычный TfidfVectorizer получает
фиксированный словарь и обучает IDF **только на train**. Сериализация использует
стандартные классы scikit-learn, собственный класс модели для загрузки не нужен.

Данные, ID, три класса, веса классов, настройки TF-IDF, C=0.5/1/2 и правило выбора
по validation macro-F1 сохранены. Конфиг не подбирался под новые результаты.
Словарь остаётся размером 100 000; validation используется только через transform.
Политика и число равных частот записаны в `run_metadata.json` → `vocabulary_selection`.

## Два полных запуска

Оба запуска на macOS arm64, CPython 3.13.7, с `OPENBLAS_NUM_THREADS=1` и
`OMP_NUM_THREADS=1`. Все версии указаны в [run_metadata.json](../run_metadata.json).
Они имеют один исходный код, конфиг, Parquet и порядок train/validation-ID.
Поле git_commit отражает базовый commit до сохранения изменений; точную
реализацию запуска фиксирует script_sha256, совпадающий с текущим train_baseline.py.

|---|---:|---:|
| 0.5 | 0.70505142 | 0.70505142 |
| 1 | 0.71664142 | 0.71664142 |
| 2 | 0.71801464 | 0.71801464 |

Точные значения в CSV; округление таблицы сверяется с ним при обновлении отчёта.
Победитель C=2, **accuracy 88,938053%, macro-F1 0,71801464**, F1 neutral 0,33889377.
Ни один запуск не выдал предупреждения о несходимости.

[Сравнение комплектов](repeat_runs.json) подтвердило:

- одинаковые словари, IDF, коэффициенты и свободные члены;
- одинаковые метрики, классы и вероятности на всех 10 396 validation-строках;
- максимальная разница вероятностей — 0;
- загрузка каждого комплекта сохраняет ответы (также [roundtrip](../bundle_roundtrip.json)).

Байты двух joblib различаются при совпавших проверенных параметрах и ответах;
причина различия сериализации здесь отдельно не устанавливалась.
Побайтовое совпадение новых обучений не является критерием; суммы каждого
файла сохранены. Принят **второй** комплект:

- SHA-256 файла: `1e33b5cfe7bd3738800f89696a85e604fe05291dc031991ca187e3d39de0c211`;
- TF-IDF: `5e7e2cd53315e896afc9d37224370102c136f8dfdcf38aad9e7dfc8bfa5f9f15`.

Сравнение выполнено отдельным процессом:

```bash
python tools/verify_baseline_repeats.py
```

Для повторения сначала сохраните `run_metadata.json`, `winner_config.json`
первого обучения и его модель как `baseline.joblib` в отдельный локальный
каталог; после второго обучения передайте этот каталог через `--first-dir`.
Текущая копия первого запуска — `artifacts/t04-reproducibility/stable-first/`.
Тайминги этих повторов не являются сравнительным бенчмарком: диагностические
проверки могли выполняться параллельно.
