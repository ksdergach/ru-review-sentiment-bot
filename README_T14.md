## Что оценивается

Для каждой из 36 записей один и тот же классификатор получает два входа:

1. **Эталон:** ручная транскрипция T11 → классификатор → тональность.
2. **ASR:** аудио → Whisper → тот же классификатор → тональность.

Классификатор — выбранный в T12 baseline (`bot_model`, `voice_protocol.backend`).
Обе классификации идут через `predict_batch` общего интерфейса `src.classifier`
с одним объектом модели, по одному тексту за вызов (`batch_size=1`) и с лимитом
`max_text_length=2000`, как у бота. Текст длиннее лимита — ошибка классификатора для
этой записи, без скрытого усечения. WER-нормализация ко входу классификатора не
применяется. Распознавание — `src.speech.SpeechRecognizer` с параметрами фиксации,
без скачивания модели. Код бота не менялся.

Классы и порядок: `negative = 0`, `neutral = 1`, `positive = 2`; служебное «нет
предсказания» — `-1` (в построчных записях — `error`).

## Метрики

**Классификация** (оба режима, все 36 записей):

- macro-F1 строго по трём классам; класс без предсказаний остаётся в среднем;
- accuracy, precision, recall, F1, support каждого класса — существующая
  `validation_metrics` из `src/train_baseline.py` (`labels=[0, 1, 2]`, `zero_division=0`);
- верно / неверный класс / нет предсказания;
- матрица 3×4: строки — истинный класс, столбцы — три класса и `error`;
- `ΔF1 = F1_ASR − F1_reference`.

**Распознавание** — корпусный WER по всем 36 записям:

```text
WER = (ΣS + ΣD + ΣI) / ΣN
```

S, D, I — замены, удаления, вставки минимального выравнивания слов (Левенштейн),
N — слова эталона после нормализации. Суммы берутся по всем записям, а не
усредняются WER отдельных записей; WER может превышать 1. Сумма S + D + I равна
расстоянию существующей `tools.report_nlp_data_quality.word_error_rate`; T14 только
раскладывает его по видам. Среди равноценных выравниваний выбирается замена, затем
удаление, затем вставка; сумма от этого не зависит.

Нормализация утверждена в T12 и переиспользуется без изменений —
`tools.report_nlp_data_quality.words`: Unicode NFC → casefold → символы категории
Unicode P заменяются пробелами → разбиение по пробельным символам. `ё` и `е`
различаются; цифры остаются цифрами, числительные в слова не переводятся. Правило
одинаково для эталона и ASR. Иная нормализация запуском не принимается.

## Пустые ответы и сбои

| Ситуация | Статусы | Предсказание | WER |
|---|---|---|---|
| успех | `asr_status=ok`, `asr_classification_status=ok` | класс | S/D/I выравнивания |
| пустая транскрипция | `asr_status=empty`, `not_run` | `error` (-1) | пустая гипотеза: D = N |
| технический сбой Whisper | `asr_status=error`, `asr_error_code`, `not_run` | `error` (-1) | пустая гипотеза: D = N |
| ошибка классификатора на эталоне | `reference_status=classifier_error` | `error` в режиме эталона | не зависит |
| ошибка классификатора на тексте Whisper | `asr_status=ok`, `asr_classification_status=classifier_error` | `error` в режиме ASR | S/D/I выравнивания: расшифровка не обнуляется |

- Ни одна запись не исключается: метрики и WER считаются по всем 36, состав
  сверяется с ID фиксации.
- `error` — служебное «нет предсказания», не четвёртый класс: оно снижает recall
  истинного класса и не входит в среднее F1. В `neutral` или другой класс оно
  не превращается.
- Пустые ответы, сбои Whisper (с кодом) и ошибки классификатора (с типом ошибки)
  дополнительно считаются отдельно.
- Ошибкой классификатора считаются исключения его контракта (`ClassifierError`,
  `InvalidTextError`, например текст длиннее 2 000 символов). Иные исключения
  означают дефект и прерывают оценку без записи результатов.
- Пустой эталон (нет слов после нормализации) — ошибка предусловий до загрузки моделей.

## Время

По каждой записи (`perf_counter`): `asr_seconds` (`SpeechResult.elapsed_seconds`:
декодирование и полное чтение сегментов), `reference_classifier_seconds`,
`asr_classifier_seconds`, `total_seconds` (распознавание и классификация результата
Whisper подряд, как в боте). Для сбоев сохраняется время до отказа и статус.

До основного прохода и отдельно от него измеряются загрузка классификатора,
его прогрев одним вызовом на трёх фиксированных `_smoke_texts()`, загрузка Whisper
и **обязательный** прогрев Whisper одним проходом отладочной записи T16
(SHA-256 `d6a29c51a3e22a08dafcbfdd045769bd4c6481f982e9ec03b7f91f382a0fa530`, 204 813 байт).
Записи T11 для прогрева не используются; прогрев в метрики не входит. Без этой записи
или при несовпадении её размера или суммы запуск отказывает до валидатора T11; если
прогрев вернул не `ok`, оценка останавливается до первой записи T11.

В сводке по каждому этапу — количество, сумма, среднее, медиана и p95 (linear)
**по всем 36 записям**, как требует п. 7 протокола T12. Невыполненный этап
(классификация ASR при пустом ответе или сбое Whisper, статус `not_run`) построчно
остаётся пустым со своим статусом, а в основную сводку входит с нулевым временем.
Если такие записи есть, этап дополнительно описывается отдельной статистикой
`executed_calls` — только по фактически выполненным вызовам, со своим количеством;
в `report.md` она выводится строкой «только выполненные вызовы». Для сбоя
классификатора этап выполнен: учитывается время до отказа. В финальном запуске
все этапы выполнены во всех 36 записях, поэтому `executed_calls` в `metrics.json`
нет, а опубликованные агрегаты от этого правила не зависят.
Сетевая задержка Telegram не измеряется. Условия финального запуска —
[«Условия измерения времени»](#условия-измерения-времени).

## Конфиденциальность публичных результатов

- **Проблема.** Первоначальный публичный `predictions.csv` (по п. 8 раздела T14
  протокола T12) содержал предсказания обоих режимов по каждому ID. Вместе с двумя
  точными матрицами ошибок из `metrics.json` и `report.md` это оказалось небезопасно.
  Из первоначальной опубликованной версии однозначно выводились эталонные метки пяти
  записей, ещё у шестнадцати оставалось по два возможных варианта.
- **Решение.** Координатор утвердил вариант В1: из публичного построчного
  представления удалены индивидуальные предсказания (`reference_prediction`,
  `asr_prediction`). Новый файл получен детерминированным удалением этих двух
  столбцов из оригинального CSV (`redact_public_predictions_csv`), без инференса.
  ID, порядок строк, статусы, коды ошибок и время не изменились.
- **Что сохранено.** Оригинальные результаты единственного эксперимента сохранены
  без изменений в закрытых материалах: полные построчные результаты в
  `artifacts/t14/records.json` и оригинальный CSV (SHA-256 `776d074c…6dc5`).
  Копия оригинального CSV в рабочее дерево Git не добавляется. `metrics.json` и
  `report.md` остались побайтно прежними.
- **Что не менялось.** Численные результаты, методика, правила измерения, модели и
  входы T12 не менялись. Исключение относится только к форме публичной публикации
  T14, а не к пересмотру протокола измерений.
- **Защита.** Оценщик пишет публичный CSV уже в формате В1. Перед публикацией
  `assert_no_label_disclosure` целочисленной программой проверяет, совместима ли
  с обеими матрицами и построчными публичными полями (статусы, коды ошибок, время,
  списки ID сбоев) больше чем одна метка каждой записи. Если хотя бы одна метка
  однозначна — например, когда технический сбой единственный в столбце `error`, —
  публичные файлы не пишутся: команда завершается с кодом 3 (`BLOCKED`) до
  отдельного решения координатора. Приватные результаты при этом сохраняются.
  Сбои не скрываются, записи из расчётов не исключаются. Сообщение называет только
  число записей, без ID и меток.
- **Проверка.** В опубликованном представлении В1 для каждой из 36 записей
  совместимы все три метки.
- **История Git.** Первоначальная версия файла остаётся в истории PR #45.

## Проверка

```bash
python -m pytest -q tests/test_evaluate_voice.py tests/test_voice_eval_public_results.py
```

Тесты используют искусственные тексты, файлы, комплекты и фиксацию в схеме T12,
а также подменные Whisper, классификатор, git и проверку среды. Ожидаемые значения
посчитаны вручную. Проверяются:

- адаптер схемы T12 и, если в рабочей копии есть `reports/freeze.json`, извлечение
  полей из настоящей фиксации (только публичный файл);
- утверждённая нормализация (ё/е, цифры, пунктуация, NFC) и совпадение S + D + I
  с `word_error_rate`;
- корпусный WER, его отличие от среднего по записям, пустая гипотеза при пустом
  ответе и сбое Whisper, отдельный учёт сбоев;
- macro-F1 по трём классам, в том числе при классе без предсказаний и при `-1`;
- пять видов исхода и полнота записей, публичный `predictions.csv` без текстов;
- сводка времени по всем записям: нулевой вклад невыполненного этапа и отдельная
  статистика `executed_calls` — для пустого ASR, технического сбоя, смешанного набора
  и прежняя форма сводки, когда все этапы выполнены;
- обязательный прогрев T16: отсутствие файла, чужой файл, файл T11, сбой прогрева;
- отказы при изменённой или неутверждённой фиксации, закреплённых файлах,
  параметрах Whisper, комплектах моделей, среде, git, неполном или изменённом T11 —
  до доступа к T11 и моделям, где это предусловие;
- отсутствие приватных текстов в публичных отчётах, неизменность входов;
- защита от восстановления меток: механизм первоначального формата, сбои Whisper и
  классификатора, единственный сбой в финальном запуске блокирует публичные файлы
  и сохраняет приватные, детерминированное удаление столбцов.

`tests/test_voice_eval_public_results.py` работает только с публичными файлами
рабочего дерева и искусственными данными, без истории Git:

- `metrics.json` и `report.md` побайтно оригинальны, `predictions.csv` — формат В1;
- арифметика агрегатов: классовые метрики, macro-F1, accuracy, ΔF1, WER, сбои, время;
- в публикации В1 однозначная метка не выводится ни для одной записи;
- на искусственном наборе первоначальный формат раскрывает метки и блокируется,
  а его детерминированное сокращение до В1 меток не раскрывает.
