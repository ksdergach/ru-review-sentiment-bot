# T05 — проверка вычислительных ресурсов для RuBERT и faster-whisper

Методика скрипта: `t05.2` (записана в каждом отчёте). Отчёты, созданные более ранней версией скрипта (без поля `methodology`
или с другим значением), считаются устаревшими и должны быть пересозданы запуском, описанным ниже.

## 1. Что проверяет T05

Задача отвечает на один вопрос: **хватает ли ресурсов на машине защиты** (Windows 10, Intel Core i5-13420H, 16 GB RAM,
NVIDIA GeForce RTX 4050 Laptop 6 GB), чтобы в одном процессе выполнить и обучение RuBERT, и распознавание речи Whisper.

`PASS` в отчёте означает, что скрипт **реально** выполнил и проверил следующее:

| Что | Как проверяется |
|---|---|
| RuBERT `cointegrated/rubert-tiny2` | Реальная загрузка, 3 класса (`negative`=0, `neutral`=1, `positive`=2). Параметры модели и входные тензоры лежат на устройстве профиля |
| Forward / backward / optimizer | 3 реальных шага AdamW на маленьком батче из общего train T04. Батч дополняется до `max_length` (это намеренная нагрузка на память) |
| Encoder и head обновились | Градиент > 0 и значение изменилось после `optimizer.step()` у весов первого и последнего слоя энкодера (`encoder.layer.N`) и у `classifier.*`. Одни embeddings не считаются доказательством |
| faster-whisper | Реальное распознавание отдельной отладочной русской записи; все `segments` дочитываются **внутри** замеряемого интервала (иначе таймер измерял бы только создание ленивого генератора) |
| Совместная работа | RuBERT и Whisper загружены одновременно; порядок операций RuBERT → Whisper → RuBERT; логиты RuBERT до и после Whisper совпадают |
| Время | Первый (холодный) шаг RuBERT и устоявшийся шаг отдельно; загрузка моделей; распознавание при первом вызове и повторное при загруженном RuBERT; RTF |
| Память | Пиковый RSS процесса по данным ОС за весь прогон, выборочный пик по этапам, минимум свободной системной RAM, CUDA peak allocated / peak reserved / занято на устройстве |
| Происхождение данных | `train.parquet` и список ID совпадают по SHA-256 с `reports/baseline/run_metadata.json` (T04); все ID входят в сплит `train` из T03 `split_ids.csv` |

Скрипт **не** проверяет и не заявляет: полное обучение RuBERT, качество распознавания (WER), Telegram-бот, сквозной сценарий,
удалённый GPU / VDS / Colab (см. раздел 8).

Финальные 36 голосовых записей и финальный текстовый test **не используются**. Для проверки нужна отдельная отладочная запись.

## 3. Профили

| Профиль | RuBERT | Whisper |
|---|---|---|
| `primary` | CUDA, batch 8, max_length 256, fp16 | `small`, CPU, int8, beam 5, VAD, 8 потоков |
| `reserve` | CUDA, batch 4, max_length 128, fp16 | `base`, CPU, int8, beam 1, VAD, 6 потоков |

`reserve` — это **более лёгкая локальная конфигурация** той же машины. Это не внешние вычисления. Скрипт проверяет, что
`reserve` строго легче `primary`. Whisper намеренно оставлен на CPU: не переносите его на GPU ради красивого результата, для
CUDA-режима faster-whisper/CTranslate2 нужны собственные CUDA 12 cuBLAS и cuDNN 9, наличие PyTorch CUDA этого не доказывает.

## 4. Подготовка

Все команды выполняются из корня репозитория в PowerShell.

Сначала установите общее окружение по [README.md](README.md), выбрав CUDA-сборку
PyTorch (в сохранённых отчётах команды — `2.10.0+cu126`). После выбора сборки:

```powershell
python -m pip install -r requirements.txt
```

**Защита Git.** Скрипт отказывается работать, если папка с расшифровкой или файл отладочного аудио могут попасть в коммит.
Проверьте:

```powershell
git check-ignore -v artifacts/resource_check/primary/whisper_result.json
```

Если вывод пустой, добавьте в `.gitignore` (для `models/` и `*.joblib` — только если их там ещё нет):

```text
artifacts/
*.m4a
*.wav
*.mp3
*.ogg
*.oga
models/
*.joblib
```

Расшифровки, отладочное аудио, кэш Hugging Face, модели и секреты (`.env`, токены) не коммитятся.

## 5. Команды

Тесты (быстрые, без загрузки моделей и без GPU):

```powershell
python -m pytest tests/test_resource_check.py -q
```

Предварительная проверка окружения и данных (модели не запускаются). Аудио можно указать заранее, тогда проверятся его размер,
длительность и Git-безопасность:

```powershell
python src/check_resources.py --preflight --profile primary --audio "<путь>\debug_ru.m4a"
```

Реальные запуски. Флаг `--confirm-debug-audio` — ваше явное подтверждение, что файл является отдельной отладочной записью, а не
одной из финальных 36:

```powershell
python src/check_resources.py --profile primary --audio "<путь>\debug_ru.m4a" --confirm-debug-audio
python src/check_resources.py --profile reserve --audio "<путь>\debug_ru.m4a" --confirm-debug-audio
```

Перед замером закройте лишние программы (браузер, мессенджеры, IDE): запас оперативной памяти на этой машине небольшой.

Повторный запуск с прогретым кэшем (первый запуск скачивает модели, и время загрузки Whisper включает скачивание). Флаг
`--offline` заодно доказывает, что обе модели загружаются из локального кэша без сети, как это будет на защите:

```powershell
python src/check_resources.py --profile primary --audio "<путь>\debug_ru.m4a" --confirm-debug-audio --offline
```

Каждый запуск сначала удаляет старые отчёты своего профиля: неудачный повторный запуск не оставит устаревший `PASS`.

Коды возврата: `0` — PASS; `2` — ошибка проверки, конфигурации, данных или защиты (сообщение начинается с `T05 ERROR`);
`3` — непредвиденная ошибка; `4` — не хватило памяти CUDA/RAM (это результат для профиля: запустите `reserve`).

## 6. Как читать результат

`status: PASS` в `resource_report.json` вычисляется из результатов этапов, а не задан константой. Дополнительно:

* `has_resource_warnings` — есть предупреждения по запасу памяти (свободная RAM ниже 1 GiB, свободная VRAM ниже 1 GiB),
  Whisper медленнее реального времени или из чекпойнта RuBERT не загружено что-то, кроме нового `classifier.*`. Это не FAIL:
  профиль работает, но с малым запасом, и это нужно указать в отчёте.
* `memory.process_peak_rss_mib_os` — пик RSS процесса за весь прогон по данным ОС (на Windows — peak working set). Выборочные
  значения (`*_sampled`) берутся с шагом 50 мс и могут пропустить короткий всплеск.
* `rubert.cuda_peak_allocated_after_backward_mib` зависит от `max_length` (активации); общий пик за шаг определяется в основном
  состоянием оптимизатора. `peak reserved` — то, что реально удерживает драйвер.
* `rubert.step_seconds_first_cold` включает прогрев CUDA, `step_seconds_steady_mean` — устоявшееся время шага.
* `whisper.transcription_seconds` — первый вызов; `joint_load.whisper_while_rubert_loaded.transcription_seconds_warm` — повторный
  при загруженном RuBERT. RTF = время распознавания / длительность аудио.
* Язык распознавания задан явно (`ru`), поэтому `language_probability` не считается доказательством определения языка.

Ожидаемые и не являющиеся ошибками предупреждения:

* Hugging Face: `classifier.weight` / `classifier.bias` в состоянии MISSING и `cls.*` в состоянии UNEXPECTED — 3-классовая голова
  создаётся заново, в чекпойнте `rubert-tiny2` её нет. Скрипт сам сообщает это как INFO.
* Hugging Face: предупреждение об отсутствии `HF_TOKEN` и о символических ссылках в кэше Windows — не блокируют работу.

FAIL — любое из: `T05 ERROR` / код возврата не 0; в JSON нет `"status": "PASS"`; `encoder_updated` или `head_updated` не `true`;
`rubert.device` не `cuda`; фактическая длина тензора не равна `max_length`; `transcription_measured_with_all_segments_consumed`
не `true`; `segment_count` равен 0; логиты RuBERT после Whisper изменились; отчёт содержит поле `methodology`, отличное от `t05.2`.

## 7. Что можно и нельзя коммитить

Можно: `src/check_resources.py`, `configs/resource_check.json`, `tests/test_resource_check.py`, `README_T05.md`, каталог
`reports/resources/`. В отчётах есть только длина расшифровки, её SHA-256, тайминги и агрегаты; перед записью скрипт ищет в них
любой фрагмент расшифровки и текстов батча (в том числе под другим именем поля) и при находке ничего не записывает.

Нельзя: `artifacts/`, отладочное аудио, расшифровки, модели, кэш Hugging Face, `.env` и любые токены.

## 8. Ограничения и остаточные риски

* Отчёт подтверждает только свой профиль, на своей машине, в момент запуска. Другой набор открытых программ даёт другой запас RAM.
* Размер RAM, видимый ОС, может быть меньше установленных 16 GB (часть резервируется прошивкой и встроенной графикой) — в отчёте
  записано значение, которое видит ОС.
* Замеры сделаны с `mixed_precision=fp16`; если T06 будет обучаться в другой точности или с другим `max_length` / batch, память
  нужно измерить заново.
* Время распознавания измерено на конкретной записи; для записи длиной 30 секунд время можно только оценить по RTF, это не замер.
* Внешние вычисления (удалённый GPU, VDS, Colab) скриптом **не проверяются**; в отчёте их статус — `NOT_VERIFIED_NOT_CLAIMED`.
  Доступ считается подтверждённым только после явного `confirmed_by_human=true` с указанием провайдера в конфиге, и даже тогда
  скрипт лишь фиксирует заявление человека, а не проверяет доступ.
