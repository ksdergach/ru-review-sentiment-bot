# ru-review-sentiment-bot

Учебный проект: голосовой отзыв Telegram → Whisper → текстовый классификатор
→ `negative=0`, `neutral=1`, `positive=2`.
[План](docs/team_plan.md) и [доска](https://github.com/users/ksdergach/projects/2).

Текущий приоритет — [сдача NLP без трансформеров](docs/nlp_submission.md):
TF-IDF + Logistic Regression, качество данных, анализ ошибок и короткий отчёт.
[Milestone](https://github.com/ksdergach/ru-review-sentiment-bot/milestone/1)
собирает задачи этой сдачи; RuBERT не входит в её обязательный объём.
Отдельный эксперимент [T06](README_T06.md) дообучает RuBERT на том же train.
[Качество данных и транскрипций](reports/nlp/data_quality.md): показатели
корпуса проверены; пользователь подтвердил эталон 12-секундного фрагмента,
WER = 0% (0 ошибок / 24 слова). N01 завершена; результат ASR относится только к этому фрагменту.

T03/T05 приняты по [проверке 03.10.2026](reports/acceptance/2026-10-03.md).
[T04 принята 07.10.2026](reports/baseline/reproducibility/README.md):
зафиксирован однозначный отбор признаков и проверен повтор обучения.
Актуальная validation accuracy — **88,94%**, macro-F1 — **0,7180**;
исходные Windows-результаты сохранены в архиве.

Для N02 подготовлены [метрики и разбор 40 ошибок](reports/nlp/baseline_analysis.md)
на принятом 07.10.2026 детерминированном Mac-комплекте (после T04). Полная validation:
accuracy 88,9381%, macro-F1 0,718015; финальный test не использован.
[Протокол](reports/nlp/baseline_reproducibility.md) фиксирует решение по отбору признаков;
человеческая проверка 40 ошибок ожидается.

T02 завершена: [аудит 100 отзывов агентом](reports/dataset/agent_review.md)
и [подтверждение пользователем 15 случаев](reports/dataset/manual_review.md).
В №63 и №94 согласован neutral; исходная разметка датасета сохранена.

В репозитории уже есть подготовка данных (T03), обучение baseline (T04),
проверка ресурсов (T05) и модуль распознавания голоса (T08).
Baseline-часть общего интерфейса классификатора и текстовый Telegram-бот
реализуются в N03 (#26). Для RuBERT выполнена полная эпоха [T06](README_T06.md):

Голосовой режим Telegram-бота добавлен в T09 (#11): [запуск и проверка](#голосовой-telegram-бот-t09);

## Установка

Проверяемая версия — **CPython 3.13.7** (`.python-version`); она совпадает
с версией в сохранённых отчётах T04/T05. Нужен рабочий Git в PATH:
`git --version` должен завершаться успешно. Команды ниже выполняются
из корня этого репозитория. Для установки нужен интернет; для быстрых проверок
не нужны GPU, токен Telegram, веса моделей и финальные тестовые записи.

Получите проверяемую версию: основная ветка — `master`; для независимой проверки
перейдите на конкретный commit и запишите его SHA в протокол.

```bash
git clone https://github.com/ksdergach/ru-review-sentiment-bot.git
cd ru-review-sentiment-bot
git checkout <commit SHA>   # или master
git rev-parse HEAD
```

Создайте новое окружение. Если `.venv` уже содержит другой проект или версии,
создайте отдельное окружение, а не устанавливайте поверх него.

macOS / Linux:

```bash
python3.13 --version
python3.13 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
py -3.13 --version
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

В обоих случаях вывод версии должен быть `3.13.7`.
Если активация запрещена политикой PowerShell, вызывайте
`.\.venv\Scripts\python.exe` вместо `python`; менять системную политику не нужно.

**Выберите один вариант установки PyTorch**, затем установите общие зависимости.
Версия `torch==2.10.0` в requirements допускает сборки `+cpu` и `+cu126`.

macOS Apple Silicon:

```bash
python -m pip install -r requirements.txt
```

Linux / Windows без NVIDIA GPU — сначала CPU-сборка, чтобы не загружать
ненужные CUDA-библиотеки:

```bash
python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

Машина команды с NVIDIA, использованная в T05:

```powershell
python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r requirements.txt
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Варианты сборок соответствуют [инструкциям PyTorch 2.10](https://pytorch.org/get-started/previous-versions/#v2100).
CUDA должна быть доступна для профилей T05. Общие тесты выполняются и на CPU;
они не подтверждают доступность GPU или способность обучить модель на конкретной машине.

Версии научных библиотек закреплены по отчётам T04/T05, чтобы не менять окружение
уже обученного baseline. aiogram и pytest также закреплены и проверяются импортом.
Прямые зависимости находятся в `requirements.txt`; полный снимок локальной
проверки с транзитивными зависимостями — в `reports/environment/`.
Снимок одной ОС не является универсальным lock-файлом для CUDA и всех платформ.

### Декодирование аудио

Установленный PyAV используется faster-whisper и поставляет библиотеки FFmpeg
в бинарном пакете: отдельная команда `ffmpeg` для текущего пути распознавания
не обязательна ([описание faster-whisper](https://github.com/SYSTRAN/faster-whisper#requirements)).
Для ручной конвертации записей можно дополнительно установить FFmpeg:
`brew install ffmpeg` на macOS, `sudo apt install ffmpeg` на Ubuntu
или `winget install --id Gyan.FFmpeg -e` в Windows.
Проверка такой установки — `ffmpeg -version`.

## Быстрая проверка окружения

```bash
python -m pip check
python tools/check_environment.py
python -m pytest -q
python src/train_baseline.py --smoke-test
```

`check_environment.py` сверяет Python и версии пакетов, импортирует в том числе
реальные классы BERT, Whisper и aiogram. Он не скачивает модели и не читает датасет.
Ненулевой код возврата означает несовместимую версию или ошибку импорта.
Smoke-тест baseline обучается на встроенных искусственных примерах во временной
директории; это проверка установки, не эксперимент на финальном test.

Тесты используют временные данные. Финальные текстовые метрики и 36 голосовых
отзывов для этих команд не нужны. Отчёт о выполненной проверке T01 —
[reports/environment/verification.md](reports/environment/verification.md).

## Точки входа

Сначала можно посмотреть справку без запуска обучения:

```bash
python src/prepare_data.py --help
python src/train_baseline.py --help
python src/check_resources.py --help
```

Подготовка данных и обучение — отдельные команды:

```bash
python src/prepare_data.py --config configs/data_prep.json
python src/train_baseline.py --config configs/baseline.json
```

Эти команды создают локальные данные/модель и обновляют отчёты своего этапа.
Проверяйте изменения отчётов перед коммитом. T03 проверяет целостность всех
сплитов; T04 обучается на train и выбирает параметры по validation, не оценивая
финальный test. Подробности: [T03](README_T03.md), [T04](README_T04.md).

Дообучение RuBERT: [команды, бюджет и обработка текстов T06](README_T06.md).
Точка входа — `python -m src.train_transformer --config configs/transformer.json`;
она сверяет train-ID и версию данных с baseline и выбирает checkpoint по validation macro-F1.

Готовую обученную модель RuBERT переобучать не нужно. Она скачивается вне Git одной
командой, одинаковой для Windows, macOS и Linux:

```bash
python tools/fetch_transformer.py
python tools/restore_nlp_splits.py
python tools/verify_transformer.py
```

Первая команда скачивает архив с Google Диска и проверяет SHA-256. Затем она
восстанавливает комплект в `models/transformer/`; повторный запуск ничего не
перезаписывает. Две другие команды проверяют модель. Поддерживаемые платформы,
ручная установка из архива и решения типичных проблем описаны в
[README_T06.md](README_T06.md#получение-готовой-модели-без-обучения).

Проверка ресурсов после получения локальных данных T03 и артефактов T04:

```bash
python src/check_resources.py --preflight --config configs/resource_check.json --profile primary
```

Это проверка условий запуска, не реальный шаг обучения.
Профили `primary` и `reserve` в текущем конфиге предназначены для Windows-машины
команды с CUDA. На Mac или машине без CUDA их отказ ожидаем; проверка импортов
T01 от этого не зависит. Для другого оборудования нужен отдельно проверенный
конфиг, а не заявление о пройденной T05.

Реальные замеры с отладочным аудио и условия использования `--confirm-debug-audio`
описаны в [T05](README_T05.md). Финальные 36 записей для них не используются.

Telegram-бот (текстовый и голосовой режимы) запускается отдельной точкой входа
`python -m src.bot`; см. [T09](#голосовой-telegram-бот-t09).

Распознавание отдельной отладочной записи модулем T08:

```bash
python -m src.speech artifacts/audio/debug.ogg --allow-download --show-text
```

Замените путь на свою запись. Первый запуск скачает зафиксированную модель;
после него `--allow-download` можно убрать. Контракт для бота, обработка пустой
речи, ошибок и временных файлов описаны в [README_T08.md](README_T08.md).
Состав финальных 36 голосовых отзывов и его проверка — [README_T11.md](README_T11.md).
Оценка влияния Whisper на этих записях (T14) выполнена одним финальным запуском
`tools/evaluate_voice.py` по утверждённой фиксации T12: macro-F1 0,8299 на эталонных

## Что хранится в Git

Исходные `NLP_dataset/*.parquet` уже отслеживаются и сохраняются без изменений.
Конфиги, решения по дубликатам, контрольные суммы, ID без текстов, код и
агрегированные метрики также сохраняются.

Новые записи кладите в `artifacts/audio/`, результаты с текстами —
в `artifacts/`, модели — в `models/`, производные данные — в `data/processed/`.
Кэш `.cache/`, локальные окружения, `.env` и его варианты, аудио, видео,
сериализованные модели, токенизаторы и checkpoints исключены через `.gitignore`.
JSON с текстами вне этих локальных каталогов автоматически не исключается:
не сохраняйте расшифровки в `reports/`.

Проверка правил без создания файлов:

```bash
git check-ignore -v .env .env.local artifacts/audio/debug.wav models/baseline/model.joblib checkpoints/run/model.safetensors .cache/huggingface/tokenizer.json data/processed/train.parquet
git check-ignore --no-index NLP_dataset/train-00000-of-00001.parquet .env.example configs/data_prep.json reports/environment/verification.md
```

Первая команда должна вывести правило для каждого локального артефакта.
Вторая должна не вывести ничего и завершиться с кодом 1: перечисленные исходники,
шаблон, конфиг и отчёт не игнорируются. Уже отслеживаемый файл не скрывается
добавлением в `.gitignore`; перед коммитом проверяйте `git status --short`.

## Текстовый Telegram-бот N03

N03 (#26) подключает baseline TF-IDF + Logistic Regression
к текстовым сообщениям Telegram.

Текстовый режим использует общий `src.classifier.predict`.
Бот не обучает модель и не содержит отдельной реализации классификатора.

Поддерживаются:

- `/start`;
- `/help`;
- текстовые киноотзывы длиной до 2000 символов включительно;
- классы `negative`, `neutral`, `positive`;
- вывод метки и уверенности модели;
- обработка пустого и слишком длинного текста;
- обработка неизвестных команд, помеченных Telegram как команды;
- отзывы с `/` в начале без признака команды поступают в классификатор;
- один запрос к модели за раз в отдельном потоке; при занятости - просьба повторить;
- понятное сообщение при недоступности модели;
- отклонение стикеров, документов и других неподдерживаемых сообщений
  (голосовые сообщения принимаются начиная с T09).

Бот предназначен для киноотзывов. Для произвольных текстов вне этой
предметной области результат классификации не следует интерпретировать
как содержательную оценку.

Уверенность модели не является гарантией правильности классификации.

### Модель

Для N03 ожидается локальный файл:

```text
models/nlp_baseline/tfidf_logreg_baseline.joblib
```

Он не хранится в Git. Путь читается из `model_dir` и `bundle_name`
в `configs/nlp_baseline.json`, относительно корня репозитория.

Конфигурация N03:

```text
configs/nlp_baseline.json
```

Обучение и дообучение запрещено запускать автоматически при старте бота,
в том числе при отсутствии файла модели. В этом случае бот отвечает сообщением
о недоступности классификации. Локальное обучение выполняется отдельной командой:

```bash
python src/train_baseline.py --config configs/nlp_baseline.json
```

Важно: локально переобученный комплект нельзя автоматически считать
тем же самым принятым комплектом, который использовался при приёмке T04/N02.

Команда локального обучения может перезаписать
`reports/nlp/training/run_metadata.json`. Поэтому сравнение модели
с метаданными, созданными этим же локальным запуском, не подтверждает
её соответствие принятому baseline.

Для финальной сквозной проверки N03 необходимо использовать принятый
bundle либо сравнить SHA-256 локального файла с контрольной суммой
из `run_metadata.json`, зафиксированного в принятом коммите T04/N02.

Например, если известен хеш принятого коммита:

```powershell
$acceptedCommit = "<хеш принятого коммита>"
$acceptedJson = git show "${acceptedCommit}:reports/nlp/training/run_metadata.json" | Out-String
$acceptedMetadata = $acceptedJson | ConvertFrom-Json
$actual = (Get-FileHash models\nlp_baseline\tfidf_logreg_baseline.joblib -Algorithm SHA256).Hash.ToLower()
$actual -eq $acceptedMetadata.bundle_sha256
```

Вместо `<хеш принятого коммита>` необходимо указать хеш коммита,
в котором зафиксированы принятые результаты T04/N02.

Результат `True` означает, что SHA-256 локального bundle совпадает
с контрольной суммой именно из принятого состояния репозитория.


### Выбор модели и общий интерфейс (T07)

По умолчанию используется baseline. Для RuBERT установите принятый комплект T06
командой `python tools/fetch_transformer.py` (подробности в `README_T06.md`) и
выберите backend перед запуском процесса:

```bash
export CLASSIFIER_BACKEND=rubert
python tools/predict_text.py 'Отличный фильм, понравился сюжет'
python -m src.bot
```

Оба пути вызывают `src.classifier.predict(text)`. Ответ содержит `label`,
`label_id`, `confidence`, `probabilities` (negative/neutral/positive) и
`truncated`. При усечении бот сообщает, что учтено только начало отзыва.
RuBERT использует CPU, tokenizer, max_length и правое усечение из сохранённого
комплекта; обработка совпадает с `src.train_transformer.predict_texts`.
Baseline не усекает текст. Общий интерфейс принимает непустые строки до
2 000 символов; это ограничение интерфейса, а не обучающих выборок.

`CLASSIFIER_MODEL_PATH` задаёт файл baseline или каталог RuBERT; относительный
путь считается от текущего рабочего каталога. `CLASSIFIER_REPORT_PATH` указывает
на `run_metadata.json` запуска, создавшего этот комплект. По умолчанию
используются `models/nlp_baseline/tfidf_logreg_baseline.joblib` с
`reports/nlp/training/run_metadata.json` (пути из `configs/nlp_baseline.json`) и
`models/transformer` с `reports/transformer/run_metadata.json`.
Перед загрузкой RuBERT сверяются все файлы комплекта и контрольные суммы,
версия данных, конфигурация обработки и порядок классов. Для baseline SHA-256
файла сверяется с отчётом до `joblib.load`, затем проверяется версия данных
(`training`): SHA-256 ID и Parquet train/validation, число строк,
`final_test_used: false`, отсутствие пересечений train/validation, выбор по
validation macro-F1, согласованность с параметрами модели и состоянием TF-IDF и
совпадение всех полей с отчётом. Параметры `TfidfVectorizer` и
`LogisticRegression`, которые используются при инференсе, должны совпадать с
объявленными в комплекте `text_processing.tfidf` и `logistic_regression`.
Проверка SHA-256 до загрузки ограничивает десериализацию файлом, записанным в отчёте из Git, но не делает произвольный
pickle безопасным. Произвольные новые веса требуют собственного проверенного
отчёта; подмена файлов вызывает ошибку. Локально переобученный baseline
принимается только вместе с отчётом своего запуска.
Отсутствующий или несовместимый комплект приводит к `ModelUnavailableError`
с путём и причиной (например, `checksum mismatch: label_mapping.json`);
`tools/predict_text.py` печатает её и завершается с кодом 1, бот отвечает
сообщением о недоступности классификации и записывает причину в журнал.

Модель загружается один раз, без сети и обучения. Backend фиксируется при
первом вызове; после изменения переменных окружения процесс надо перезапустить.
Для прямого выбора используйте `create_classifier("baseline" | "rubert", ...)`.
Для оценки на размеченных текстах предназначен `src.classifier.predict_batch(texts)`:
та же загрузка, обработка и проверка результата, что у `predict`; параметр
`max_text_length=None` снимает только ограничение длины интерактивного ввода.
`tools/evaluate_classifier.py` вычисляет через него метрики на validation
(финальный test не читается) и сравнивает матрицу ошибок с отчётом запуска:

```bash
CLASSIFIER_BACKEND=rubert python tools/evaluate_classifier.py
```

Финальное сравнение обеих моделей на test (T13) выполняет `src.evaluate` через тот же
интерфейс по утверждённой фиксации T12. Команда `python -m src.evaluate --check`
проверяет готовность и байтовую сумму test без декодирования текстов. Режим
`--run-final` запускают на машине измерений после отдельного согласования.
[Методика и команды T13](README_T13.md).

`tools/verify_transformer.py` и `tools/report_nlp_baseline.py` намеренно не
используют `src.classifier`: это независимые проверки результатов T06 и N02,
которые не должны зависеть от проверяемого кода интерфейса.
Атрибут `data_version` после первой загрузки содержит сведения о данных из
комплекта (у baseline - проверенный словарь `training`, у RuBERT - `metadata.data_version`).

Проверка T07:

```bash
python tools/fetch_transformer.py
pytest tests/test_classifier_accepted_rubert.py tests/test_classifier_accepted_baseline.py \
  tests/test_classifier_rubert.py tests/test_classifier.py tests/test_evaluate_classifier.py tests/test_bot.py -q
```

`tests/test_classifier_accepted_rubert.py` проверяет общий интерфейс на принятом
комплекте RuBERT и пропускается, если `models/transformer` не установлен.
`tests/test_classifier_accepted_baseline.py` делает то же для принятого baseline
T04/N02 и пропускается, если файла нет или его SHA-256 отличается от
`reports/nlp/training/run_metadata.json`. При подготовленной validation
(`data/processed/validation.parquet`) он также сверяет предсказания
`predict_batch` на всех строках с хешем предсказаний N02.
Синтетические BERT-комплекты в остальных тестах проверяют интерфейс и не
заменяют проверку принятой модели. Результаты проверки реальных артефактов:
[reports/classifier/verification.md](reports/classifier/verification.md).

## Голосовой Telegram-бот T09

T09 (#11) добавляет голосовой режим в тот же `src/bot.py`; текстовый режим N03
сохранён. Второго бота, сервера или базы данных нет.

```text
voice → скачивание во временный каталог → SpeechRecognizer (T08, configs/speech.json)
      → полный текст → src.classifier.predict (T07) → транскрипция + русская метка
```

- Текст и распознанная речь классифицируются одним `predict` и одним экземпляром
  классификатора, поэтому одинаковый текст получает одинаковую метку.
- Ответ: распознанный текст, тональность «отрицательная», «нейтральная» или
  «положительная» с машинной меткой в скобках (`negative=0`, `neutral=1`,
  `positive=2` не меняются) и уверенность модели — не гарантия правильности.
- Декодирование, Whisper (включая полный обход ленивых сегментов) и классификация
  выполняются в рабочих потоках; `/start` и `/help` отвечают во время обработки.
  Одновременно обрабатывается один отзыв, остальные получают просьбу повторить позже.
- Аудио сохраняется в уникальный временный каталог ОС и удаляется после
  распознавания, в том числе при отказе по размеру, ошибке, отмене и задержке
  (после завершения рабочего потока).
  Аудио и транскрипции не пишутся в журналы и в репозиторий.
- Команды (`/start`, `/help`, неизвестные) в классификатор не попадают. Аудиофайлы,
  документы, кружки, стикеры получают сообщение о неподдерживаемом формате.

### Модели

Классификатор и Whisper загружаются **один раз при старте**, до подключения к
Telegram; бот не обучает модели и ничего не скачивает. Если комплект отсутствует
или не проходит проверку, процесс завершается с кодом 1 и причиной в журнале
(`Startup failed: ...`, без токена, значений переменных и абсолютных путей).

| Компонент | Выбор | Где должен лежать | Как получить штатно |
|---|---|---|---|
| Классификатор baseline (по умолчанию) | `CLASSIFIER_BACKEND=baseline` | `models/nlp_baseline/tfidf_logreg_baseline.joblib`, SHA-256 из `reports/nlp/training/run_metadata.json` | принятый файл от участника команды; локальное переобучение — см. [«Модель»](#модель) |
| Классификатор RuBERT | `CLASSIFIER_BACKEND=rubert` | `models/transformer/` | `python tools/fetch_transformer.py` |
| Whisper | `configs/speech.json` (модель и revision закреплены) | `.cache/huggingface/` | один раз `python -m src.speech artifacts/audio/debug.ogg --allow-download` |

`CLASSIFIER_MODEL_PATH` и `CLASSIFIER_REPORT_PATH` работают как в T07. Для загрузки
Whisper используйте отдельную отладочную запись, **не** 36 финальных записей T11.

### Ограничения и сообщения

| Ситуация | Поведение |
|---|---|
| Голос длиннее 30 с или больше 5 МиБ (5 242 880 байт) по данным Telegram | отказ до скачивания |
| Скачанный файл больше 5 МиБ (в том числе без `file_size` или при неверных метаданных) | отказ до Whisper, файл удаляется |
| Бот занят другим отзывом (голос или текст) | просьба повторить позже, без очереди |
| Ответ не готов за 60 секунд | одно сообщение о задержке; результат запроса не отправляется |
| Пустая речь / тишина | «не удалось распознать речь», без тональности |
| Повреждённое аудио, ошибка ASR | безопасное сообщение, без частичного текста и тональности |
| Ошибка скачивания или классификатора | безопасное сообщение; причина — в журнале без текста |
| Распознанный текст длиннее 2000 символов | отказ по контракту `predict`, без скрытого усечения |
| Усечение RuBERT по токенам | ответ сообщает, что учтено только начало |
| Текст | как в N03: до 2000 символов |

### Надёжность (T10)

T10 (#12) дополняет T09 без изменения сценария, моделей и `predict()`:

- **Размер.** Метаданные Telegram проверяются до скачивания, фактический размер — во
  время скачивания и до Whisper: голос скачивается в буфер в памяти, который
  прерывает скачивание на первом байте сверх лимита. Лимит один —
  `MAX_VOICE_BYTES` = 5 МиБ; это же предел памяти буфера, а обрабатывается не более
  одного голосового отзыва одновременно.
- **Занятость.** Голос и текст используют один слот на процесс; проверка и захват
  слота выполняются без переключения задач, поэтому два почти одновременных отзыва
  не запускают два вычисления. `/start` и `/help` отвечают во время обработки.
- **Порог ожидания 60 секунд** (`RESPONSE_TIMEOUT_SECONDS`) отсчитывается после
  принятия отзыва и включает скачивание, распознавание и классификацию. Если ответ
  не готов, пользователь получает одно сообщение о задержке, а результат или ошибка
  этого запроса позже не отправляются. Это не жёсткий таймаут: начатый рабочий поток
  Whisper или классификатора завершается сам, следующие этапы не запускаются.
- **Ресурсы.** Слот занят, а временное аудио существует до фактического завершения
  рабочего потока — и после уведомления о задержке, и при отмене; затем аудио
  удаляется и слот освобождается. Создание каталога, запись и закрытие файла и
  удаление выполняются в рабочих потоках, а не в event loop: медленный диск не
  задерживает `/help` и уведомление о задержке. Каждая такая операция дожидается
  своего потока и при повторной отмене, поэтому каталог удаляется только после её
  окончания.
- **Диагностика.** При ошибке классификатора в журнал попадают только типы ошибки и
  её причины, без сообщений и traceback (в них бывают пути и текст отзыва); ошибка
  рабочего потока, завершившегося после отмены, журналируется по типу.

python -m pytest tests/test_bot.py tests/test_speech.py -q

Ручная проверка с реальными моделями (отдельная отладочная запись, не T11):

1. Подготовить модели по таблице выше и запустить бота командой из «Запуск».

   и одна из трёх русских меток.
4. Скопировать распознанный текст и отправить его обычным сообщением.
   Метка должна совпасть с меткой голосового ответа.
5. Отрицательный сценарий: голосовое сообщение с тишиной или длиннее 30 с.
   Ожидается понятное сообщение без метки.
6. Заполнить обезличенный протокол [reports/bot/t09_smoke.md](reports/bot/t09_smoke.md):
   дата, backend, модель Whisper, метки и результат сравнения — без токена,
