## Источник и атрибуция

По [карточке автора](https://huggingface.co/datasets/yeshpanovrustem/100k_movie_reviews_from_kz),
корпус собран с kino.kz, язык и тональность размечены одним автором вручную,
а разбиение выполнено по фильмам. Заявленная лицензия — **CC BY 4.0**;
это значение также получено из API. Атрибуция: **Rustem Yeshpanov (2026),
100,000+ Movie Reviews from Kazakhstan: Russian, Kazakh, and Code-Switched Texts**,
Hugging Face, ревизия выше; идентификатор статьи автора — `arXiv:2605.08600`.
Локальные исходные файлы сохранены без изменений; отбор русского языка и
дедупликация T03 создают отдельные производные данные.

На дату проверки доступ к файлам источника отмечен как `gated: auto`.
Публичный API позволил проверить суммы без скачивания корпуса и без принятия
условий доступа. Прямое чтение `README.md` и `sentiment_annotation_guidelines.md`
на закреплённой ревизии вернуло HTTP 401. Публичная HTML-карточка прочитана;
**полный документ правил разметки автором в этой проверке не прочитан**.
Не выдаём правила проекта ниже за дословные инструкции автора. Участник с
доступом может сверить их с оригиналом, указав ревизию и обнаруженные различия.

## Схема и исходные распределения

В `pc` ровно четыре поля Arrow типа `string`:

| Поле | Назначение |
|---|---|
| `movie_id` | Проверка разделения по фильмам; не признак модели |
| `review_text` | Исходный текст без изменения регистра, пунктуации и эмодзи |
| `review_sentiment` | Исходная метка `NEGATIVE`, `NEUTRAL` или `POSITIVE` |
| `review_language` | `ru`, `kk`, `cs`; в основной эксперимент идёт только `ru` |

В исходных файлах нет null или пустых/пробельных полей. Пересечения `movie_id`
между каждой парой сплитов равны нулю. Это не заменяет проверку дубликатов текста T03.

## Трактовка классов в проекте

Порядок: **negative=0, neutral=1, positive=2**. Исходную категорию приводим
к нижнему регистру и отображаем в этот индекс; рейтинги в метки не преобразуем.

- `negative`: преобладает отрицательная оценка фильма.
- `neutral`: нет выраженной оценки либо смешанные оценки не дают преобладающего итога.
- `positive`: преобладает положительная оценка фильма.

Это рабочие правила проекта. Смешанный отзыв с ясным отрицательным итогом
относится к negative; наличие одного положительного слова не определяет класс.
При аудите отдельно отмечаем смешанные оценки, сарказм, ожидания до просмотра,
вопросы, обсуждение без оценки и отзывы с неясным объектом отношения.
Наличие и частоту таких случаев в фиксированной выборке должен подтвердить
участник; автоматическая подготовка страницы этого не доказывает.

Neutral не означает «нерелевантное сообщение», «тишина» или `noise`.
Метки исходного test не исправляем под ожидаемые ответы. Возможные расхождения
человека с разметкой фиксируем как ограничения, не меняя обучающие файлы в T02.
Нейтральных русскоязычных отзывов мало (4 140 из 96 749), поэтому нужны macro-F1
и метрики каждого класса. Киноотзывы обучают классификатор содержания;
Telegram и Whisper добавляют голосовой ввод. Перенос на произвольные темы
и распознавание эмоций по интонации этим корпусом не подтверждены.

## Повторение аудита

После [установки окружения](../README.md), из корня репозитория:

```bash
python tools/audit_dataset.py
```

Команда без сети пересчитывает SHA-256, схему, распределения, пересечения фильмов
и сравнение с планом. Она проверяет исходники против закреплённого манифеста,
не обучает модель и не оценивает её на test. Для повторной независимой сверки
манифеста с первоисточником:

```bash
python tools/audit_dataset.py --verify-remote
```

Сеть нужна только для публичных метаданных конкретной ревизии. Изменение хеша,
схемы, меток или размеров приводит к ошибке. Не отключайте проверку TLS;
на проверенной установке Python macOS потребовалось указать системные CA:
`SSL_CERT_FILE=/etc/ssl/cert.pem python tools/audit_dataset.py --verify-remote`.
Этот путь специфичен для macOS, обычная команда остаётся основной.

## Ручной просмотр — ожидается участник

Скрипт выбирает **100 русскоязычных строк исходного train**: 34 negative,
33 neutral, 33 positive, seed=42. Внутри каждого класса ID сортируются по
SHA-256 строки `42:<record_id>`, выбираются первые строки. ID совместим с T03:
`<исходный файл>#row=<номер из 8 цифр>`, нумерация строк с нуля.
Это сбалансированная выборка для чтения, а не оценка частот или качества модели.

- В Git: [sample_ids.json](../reports/dataset/sample_ids.json), seed и алгоритм в конфиге/отчёте.
- Локально: `artifacts/dataset_audit/review.html` — 100 полных отзывов с исходными метками.
- Локально: `artifacts/dataset_audit/notes.md` — форма заметок участника.
- В Git: [manual_review.md](../reports/dataset/manual_review.md) — статус и порядок приёмки.

Повторный запуск создаёт ту же выборку и **сохраняет заполненные notes.md**.
Участник читает все 100 строк, записывает имя/дату и разбирает 10–15 пограничных
случаев с ID и аргументацией. В итоговый отчёт переносим только ID и пояснения
без копирования исходных текстов. Если 10 случаев не нашлось, честно фиксируем
это и согласуем дополнительную train-выборку, не придумывая примеры.

T02 пока не закрыта: подготовка материалов не заменяет ручной просмотр.
T04/T05 уже присутствовали в репозитории до этой проверки; она не является
заявлением, что ручной аудит был выполнен до их запусков.
